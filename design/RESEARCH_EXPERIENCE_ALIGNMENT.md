## 选择

不采用整体重画（延迟交付并覆盖已批准设计）；不采用只加聊天框（结果和行动仍分散）。采用**复用现有工作台、逐步收起配置、突出任务结果**。三段体验串在既有八入口内：表达业务 → 看到研究过程 → 判断并联系机会。

### 先交付：研究过程说人话

- 首屏顺序：当前在做什么、已取得多少原文/已分析多少、当前阻塞或完成解释、下一步操作。
- 现有许可/回执/资源快照放在可键盘展开的“执行明细”；未知、失败、取消仍必须在首屏提示，不用折叠隐藏风险。
- 已知 stopCode 映射为客户语言和可执行动作；未知 code 显示“研究已停止，请查看执行明细”，原码仅在明细中，不能猜测根因。
- 现有按钮执行语义不变：停止本页推进不伪装取消整个任务；未知结果不盲重试。原文数量与已复核机会数量保持分开，不加虚构百分比或预计完成时间。
- 后台通用研究暂未绑定许可/任务时，不显示“全网搜索已启用”。先改善旧真实状态呈现，新的查询与来源事件随后台接线一起上线。

### 随后台接线交付：描述需求后开始研究

- 自然语言/资料提炼复用原画像版本与确认机制；生成结果是草稿，需用户确认后进入任务。不得静默覆盖手改字段或已确认任务。
- 语音先做录入→可编辑文字→同一提炼流程；麦克风拒绝、识别失败、无服务时可继续文字输入。不能用系统自带但未核验的浏览器能力宣称已支持所有客户端。
- 任务显示真实可用来源范围：公开搜索可用与各平台授权连接分别展示；某平台未登录不等于所有研究无法启动。
- 动态研究协议至少区分查询尝试、搜索命中、原文成功/失败、待分析、已分析、待复核；事件绑定任务/执行代次，刷新从服务端恢复。模型思维过程不展示，展示实际工具动作与可核验状态。
- 时效、排除项、地域和服务能力来自已确认策略；索引时间不得刷新需求时间。无合格结果要区分搜索无结果、原文不可读、全部不匹配与尚未复核。

### 同次闭环验收：机会接行动

- 复用机会详情与原有联系草稿/确认机制，突出原话、原始时间及核验状态、匹配理由与反证、来源入口。
- 一键准备联系不等于已发送；草稿、用户确认、平台回执和实际回复分别记录。
- 保留资料权限、对象/内容/渠道变化使原确认失效、防重复、未知结果先核对。后台现有保护不能因简化页面被删除。

## 实施与验收顺序

1. 本次搜索代码独立审核/合并期间完成此源码审查，不等全部后端完成。
2. 下一功能批次先落研究进度信息层级与错误文案，定向 UI 状态测试和同视口实际截图；保留 R3/R4 组件体系，不触发全客户端重复构包。
3. 同时继续通用研究接已确认策略、现有许可/证据事务，随后联调同一进度页和候选入口；不得做仅演示用的假搜索入口。
4. 用户路径验收：真实业务描述→确认→真实研究→原文/判断→准备联系→反馈；包含零结果、权限不足、离线、未知结果和取消恢复。语音单独绑定实现/客户端证据。

本记录不改变完整 Goal、八入口或全行业目标，不宣称重设计、客户可用、部署或盈利已完成。正式状态继续集中在 V02 实施任务书。
