## 六组共同约束

- 八个一级入口保持。动作挂在所属对象，打开建议、详情或简报不自动采集、入库、发送、追加费用或登记跟进。
- 首发跨行业；需求类型按客户画像及真实行业表达扩展。展台只是已有公开研究样例，不能成为新准入限制、全行业默认画像或唯一分类模板。
- 新增只读数据至少区分 `加载中 / 可用 / 已完成但为空 / 未接服务 / 读取失败 / 无权限 / 已过期`。`—`/待核验不是 0；缺后台必须明确未接通，不能用设计样例充当成功回包。
- 新增快照绑定服务端认证得到的租户/用户、对象 ID、已确认画像版本、任务/运行窗口、来源和证据版本；按用途补充草稿版本或预算版本。前端不提交可自由选择的租户来取得权限。
- 客户、公开研究样例和配置示例独立。样例不可写客户库、导出为客户、发消息或触发“多找类似”真实任务；图片中的流程结构仅展示未来满足条件后的布局。
- 所有建议显示依据，应用前保留原文。用户编辑、切换画像/对象/用途、撤销引用或换身份后，旧响应不能覆盖新输入；允许可识别地重试读取或重新生成。
- 发生执行副作用的启动、追加预算、复核或发送必须先固化用户最终确认，再由服务端原子校验和幂等执行。超时/断线/查无回执属于未知，查询原请求，不盲重试、不清锁。沿用现有保护并扩展正式合同，不能仅凭新增前端字段认为已获得服务端保证。
- 金额、计数、时间必须能回到真实明细和口径；时间显示时区，来源发布时间与系统观察时间分开。主界面不暴露底层引擎、Skill、令牌或数据库配置。

## R4-01 · P12 建联短句教练

**主入口与行为**：保留原草稿编辑区，在当前 comment/dm 用途中打开短句建议。展示“引用上下文 → 建议短句 → 一个待回答问题 → 待核实内容”。主动作是人工应用建议；应用或复制均不发送。P13 继续复核最终保存全文、账号、对象、来源和版本。

当前 `generateContact` 只返回 `Promise<string>`，不能从一个字符串推定引用与身份绑定已经齐备。R4 必须提供以下结构化输出及校验；旧字符串路径只能按原草稿功能显示，不伪装成已完成的证据教练。

| 待实现数据 | 最小含义 |
|---|---|
| 建议身份 | 建议 ID、原请求 ID、商机/画像/来源证据版本、用途、输入草稿版本与内容摘要 |
| 引用上下文 | 可回到公开证据或允许外部引用且已确认资料的摘录、来源 URL/记录 ID、版本和位置；内部资料不可隐式外发 |
| 建议内容 | 当前用途的完整候选短句、明确问题、字符数；不将评论内容直接复制成私信 |
| 核查提示 | 提示类别、所指文字、依据或未知原因，例如冗长、多问题、无依据承诺；未知项不得标记为已核实 |

状态：未生成可发起 → 生成中可取消/继续编辑 → 成功进入待应用预览 → 应用后本机草稿有修改 → 保存后重新准备发送。失败提供重试并保留全文；输入已变化时建议变为过期或提示差异，不能自动替换。应用采用明确替换或局部应用动作；默认不删除人工修改。涉及效果、价格、工期等事实没有依据时只提示待核实，不补承诺。

验收目标：评论与私信互不覆盖；生成期间编辑保留；失效证据/撤销引用不继续标可信；建议应用后旧发送确认失效；公开样例只读；服务缺失可手动编辑真实草稿但不假称 AI 成功。**V1.1** 再以本客户真实发送/回复样本评价文案，不展示通用提升率或无依据 A/B 优胜者。

## R4-02 · P09 搜索解释（P05/P02 摘要复用）

**主入口与行为**：任务详情增加结果解释区，以本次任务窗口为单位展示已检查/未检查范围、独立来源与排除依据。用户可展开平台/方向明细；下一动作由真实原因决定，不能将所有情况都导向重新搜索。

待实现快照包含：快照 ID、任务/运行 ID、确认配置及画像版本、检查起止时间/时区、结果更新时间；逐平台/搜索方向/时间范围的覆盖单元、完成状态和未覆盖原因；来源去重标识、去重规则版本及证据锚点；排除分类、规则版本/人工复核身份；原执行和停止回执；有关预算引用。平台总状态只是摘要，不能代替明细。

执行完整度与筛选结果是两个维度：未开始/运行中/部分完成/已完成描述覆盖情况，有候选/待复核/全部排除/无合格机会/未知描述该范围的筛选结果。两者同时展示，不用单一结果枚举掩盖未覆盖部分；下面四类用户表达由两个维度及停止原因组合得到。

| 目标结果 | 必须展示 | 允许的下一步 |
|---|---|---|
| 访问失败或未执行 | 失败/未执行单元、原因、已完成部分和未检查范围 | 修复连接；未知请求先核对；确定未完成后再确认补查范围 |
| 预算耗尽 | 已查/未查、停止原因、上限/已耗/剩余或未知成本、停止是否已确认 | 缩小范围，或预览并确认追加预算；不清除已有结果 |
| 有内容但全部排除 | 本次完成覆盖范围、独立来源数、可展开的排除依据与口径 | 查看明细、修改条件或人工纠正，不自动入库 |
| 已查范围内无合格机会 | 完成平台/方向/时间窗口、独立来源数和未决复核数 | 调整方向或等待后续计划；不宣称全平台没有需求 |
| 部分完成 | 将不同覆盖单元上述结果并列汇总 | 只对选定未完成部分操作，不隐藏失败平台 |

计数口径：请求数、原始内容数、重复数、去重后来源数、新候选数、已人工确认机会数互不替代。重复属于去重前处理；过期/不匹配等属于去重后分类，不能简单相加。去重规则/覆盖窗口不同的跨平台计数不得直接求和。未知值保留未知；分类若可重叠必须明示，统计须可追到明细。未完成判断不计为已排除，待人工复核不等于已合格或无机会。

验收目标：单平台失败+另一平台空结果仍为部分完成；预算耗尽不显示“无新增”；读取失败不当空；全部排除能查依据；聚合数字与当前同窗口快照明细一致。**V1.1** 才利用真实成本/结果比较来源效率，首版不预测平台获客率。

## R4-03 · P06/P20/P19 策略与预算

客户文案区分三个概念：**研究用量上限**是来源数量、运行时长、模型调用等资源约束；**预计费用**是有真实计价依据的费用估算，无法计量时显示未知；**采购预算**是机会原文中的买方事实，不在任务配置中推定。图稿的“研究预算”目前指第一项，后续文案宜采用“研究用量上限”以免误解。

P03 继续负责确认业务画像与版本。需求类型建议读取该版本，在 P06/P20 修改，不给 P03 增加另一套自动生效的任务条件。若正式画像 schema 后续增加偏好类型，也仅作为建议输入，不能回写已确认任务；此项复用已有画像入口，不新增第七组主图。

**配置流程**：在既有可编辑条件旁增加需求类型、固定补证顺序、研究上限和停止条件。询价、方案比较、更换供应商等由业务画像提出并允许修改，建议不是已发生的采购事实。开店/扩产等变化默认走观察规则。P20 保留每日/间隔、多个执行时间、时区、离线与重叠策略；重新生成需求类型或关键词不能改日程或预算。P19 只读当前最终快照，不再生成建议。

| 待实现数据 | 最小含义 |
|---|---|
| 需求策略 | 用户选择的需求类型、类型描述/证据要求、观察类型、允许平台/方向，以及固定补证步骤和每步输入/结束条件 |
| 预算配置 | 预算版本、计量单位、每次运行上限；持续任务另有明确时间窗口的总上限，不能暗示一次上限覆盖无限计划 |
| 费用与消耗 | 已计费、估算与未知分开；有金额时带货币/收费范围/计价依据，有数量时带来源核验/步骤/时间等明确单位；未知成本不填 0 |
| 执行/停止 | 服务端累计消耗、更新时间、上限是否可强制执行、停止原因、停止请求与权威回执；“请求停止”与“已停止”分开 |
| 追加预算 | 原运行 ID、预算版本 budgetRevision、配置版本、已耗、拟增加值、新上限、剩余范围、涉及平台/日程变化、独立确认请求 ID |

V1.0 可按固定顺序逐步补证，不做自动路径优化。上限和停止条件必须由实际执行端执行；界面填写数字或展示估价不构成成本保证。金额无法计量时明确未知，且不能在无法约束费用的情况下靠“0元”或无效费用上限启动收费步骤。若只能限制核验条数/研究时长，则准确说明该限制，费用风险另行确认。服务无法执行所选硬上限时阻止相应执行，允许保存草稿。

追加预算前展示前后差异和影响，仅确认后提交；服务端原子比较原 run 与 budgetRevision，拒绝给已结束或已换预算版本的运行追加。不得自动加平台、频率、执行轮次或转成长期任务。追加结果未知按原请求核对，不能再次累加。原运行已完成的步骤/来源保留；取消计划不声称撤销已经发生的费用。界面停止等待、停止已请求、执行端已确认停止和计费结算分别表达，UI 显示停止不等于停止扣费。画像、来源范围、日程或预算任一变化使旧启动确认失效，并进入新的配置版本。

验收目标：上限临界值并发执行不超配；预算/日程不被 AI 重生成覆盖；P06/P20/P19 同一快照；计量未知与零消耗分开；追加确认取消无副作用；追加/停止未知保持保护。**V1.1** 再做基于真实成本/效果的补证选择和自动预算分配。

预算耗尽须由服务端明确返回可恢复性。仅已确认停止且处于可恢复暂停的运行，才允许用原 run + budgetRevision 预览并追加预算；追加成功后还需明确确认恢复，不能自动续跑。已完成、取消、终结失败或游标不能可靠续接的运行，不提供原运行追加；改为“基于未查范围创建新草稿”，保留原运行溯源和去重记录，进入 P19 重新确认。状态未知先查原回执，不能猜测为可恢复。

## R4-04 · P07/P10 机会与观察

**信息结构**：在客户范围内区分“机会”和“观察”，公开研究样例继续独立。P07 在原文和五项判断旁给出需求/变化分类及依据；P10 展示对应集合和处理状态。分类维度、复核工作流、采购阶段是三件事，不复用一个状态字段。

待实现数据：候选/商机及来源版本、目标画像版本；需求类型或变化类型；原文引用；建议类别（机会/观察/待补证）；分类规则/判断版本与人工确认记录。询价/比较/更换供应商也必须有原文依据，不因出现一个关键词即成为机会。业务变化不能自动推断有预算、有联系人或近期采购。

状态与迁移：未判断 → 建议分类 → 待人工复核；证据不足保留待补证，业务变化保留观察。观察升级为机会需新增可核验需求证据和人工确认；移动或重新分类保留历史理由。排除必须独立记录依据，不能用“隐藏到观察”代替排除或把未复核项计作已排除。具体持久写入服务未实现，须扩展现有原请求幂等和版本校验后才能开放动作。

验收目标：同一来源不在两个客户集合重复计为新机会；仅有开店/扩产信息保持观察；筛选总数来自同一授权集合；公开样例不混入统计/批量导出；分类变更失败不丢依据，未知结果不重发。**V1.1** 才综合多个事件判断研究时机，仍不得无依据升级为采购意向。

## R4-05 · P11 证据时间线与“多找类似”

V1.0 的时间线范围限定为**同一来源的版本链**，以及明确绑定该机会的人工联系/跟进和真实通道事件；下文“同项目依据”不授权跨帖子或跨平台聚合。跨来源关联按 V1.1 单独设计与验收。

**时间线**：沿用左证据/右联系准备结构，在证据区增加变化与缺口。V1.0 仅展示有可靠同项目依据的记录，不凭同名把帖子合并。每条变化包含项目身份/关联依据、事件 ID、事实类别、来源记录和原文版本、变化前后值、发布时间/实际事件时间/系统观察时间、核验状态。原文修改、预算或截止变化、明确关闭、人工联系及通道回复分别标识；没有实际时间时显示未知，不把抓取时间当发布时间。

`libraryFacts` 仅为当前单份阶段/截止快照；`TaskRun.events` 仅为执行记录，两者都不能直接转换成项目历史。来源打不开、404 或验证码不表示采购关闭；关闭必须有来源证据。来源版本、人工登记、渠道回执的证据强度分开；纠正保留原记录和关联关系，不抹掉历史。

**多找类似**：仅从用户认可、可操作的真实客户机会发起建议。先展示相似依据、原机会/画像/证据版本、建议新增词或话题、实际支持平台、原范围与增量范围、预算影响。用户可改、删、取消；应用后建立一个新任务草稿，返回 P06/P20 并在 P19 最终确认，不能点击一次就执行或联系。保留来源机会的溯源引用，不能把它当作新采集结果。

建议和草稿必须绑定原机会及版本；来源变化或画像过期时重新核验，不能把旧建议附在新机会。原人工搜索词、排除词、平台选择和预算仅按明确选择的应用方式改变，不默认继承成更大范围。任务创建/启动未知继续沿用原请求保护。公开样例可展示说明，不能由样例入口发起真实“多找类似”。

验收目标：同名不同主体不合并；变化可追到前后证据；访问失败不变“已关闭”；人工联系不冒充通道回复；取消扩展不建执行任务；新草稿显示确切增量并要求确认。**V1.1** 再引入可靠标识支撑的跨帖/跨平台关联、可纠正关联及主动扩展，不做无依据实体合并。

## R4-06 · P02 工作台简报

**信息结构**：保留首次使用引导与必要的现有待办入口，增加“值得联系 / 重要变化 / 待跟进”三组简报，不重复制造另一套客户记录。每条摘要能打开准确对象与证据或进入正确操作；打开简报不自动发送或标记已联系。

待实现数据：简报快照 ID、客户身份、业务日期/时区、画像与任务覆盖范围、最近完成检查时间和生成时间；三组条目各带稳定 ID、目标对象 ID/版本、理由、来源证据或真实跟进记录，以及是否仍有效。值得联系必须来自有依据且通过必要复核的需求，重要变化来自已核验变化，待跟进来自实际记录；不能从生成文本或点击量拼成业务成果。

状态：首次无画像/任务给下一步；未检查显示未检查；部分检查显示范围和未覆盖项；最近快照过期标出时间；读取失败提供刷新；同范围真实完成且集合为空才说暂无符合条件事项。三组可能交叉指向同一机会，不简单求和宣称“新增客户”；各组数量必须与其快照明细一致。样例只保留独立入口，不进入简报。

验收目标：缺目标时明确未找到，不打开其他客户；跨用户/画像切换不闪旧简报；旧请求不覆盖新快照；无数据和服务不可用分开；条目能返回具体证据。**V1.1** 才增加微信/企微通知与移动端，另行设计订阅、对象权限、取消与真实送达边界。
