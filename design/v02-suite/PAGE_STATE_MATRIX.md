# 页面、跳转与关键状态

范围：V0.2 完整获客版的八个入口、登录及主要二级页/操作弹窗。20 张核心设计图各有明确展示状态；同一组件的加载、校验、恢复等复用状态在下表定义。P19/P20 补齐任务启动确认和持续监控配置，不为每种错误另生成一套页面。

## 主流程核对

初次使用：P01 → P02 → P03/P04 → P16/P17 → P06（持续监控展开 P20）→ 逐平台连接/账号选择 → P19 → P05/P07 → P10/P11 → P12/P13 → P14/P15。公开样例只供预览，不走入库与发送链路。

持续使用：P08/P09 → P07 复核新增 → P10/P11 判断 → P12/P13 联系 → P14/P15 回复与下一步。账号或本机失效时转到 P16/P17/P18，处理后返回原任务，不丢配置。

## 共用弹窗与风险操作

发送使用 P13 的对象/内容/渠道确认结构；资料删除、设备撤销、暂停任务、覆盖恢复等使用同一视觉规范的确认弹窗，写明具体对象和影响，不出现无对象的“确定吗”。操作失败保留上下文，可取消返回。恢复与版本回退另展示目标版本/文件和影响摘要后确认，不能一点击就覆盖。

这份清单固定行为与复用状态，但不能替代真实可点击流程和每个操作的实现验收。用户确认图册时可按 ID 提出布局、文案或流程变更。

## 关键条件的统一定义

- P06/P20 的自动生成、人工修改保护、失败与过期响应按 [AI 搜索条件建议 R2](AI_SEARCH_CONDITIONS.md)执行；首次画像触发和重新生成是不同流程。图中词项为设计示例，实际建议需真实模型返回。
- P06 第二步延用平台表：每行选择已有连接/新建连接、执行账号和可用来源能力；必须保留当前任务草稿和返回入口。P17 关闭后回该步骤；可进入 P19 检查摘要与缺项，全部所选来源条件满足才允许启动。不能把平台登录成功当成任务已启动。
- P20 的“每日”展开执行时刻列表，“每隔”展开间隔与开始/结束窗口；时区默认本机值但必须可见、可改。平台频率限制由实际能力校验，不承诺任意高频。离线期间没有运行记录，恢复策略写入任务配置。
- P19 是摘要确认，不进行采集；点击确认启动后由服务端返回唯一任务和运行状态。失败或响应未知时先查询同一请求，不建立第二份任务。已确认画像版本被后续修改时，旧任务保留原版本并明确提示更新操作。
- P07 真实候选绑定画像后重新计算并显示证据判断；用户可修改结论和原因再确认，复核人/时间来自当前服务端身份。图中公开样例不转换成正式客户商机，批量处理不包含它。
- P11 的客户商机状态提供“生成联系草稿”入口进入 P12；图中公开样例保持只读联系准备及复制示例。生成仅引用允许对外使用的资料，评论/私信等用途分别生成与保存，不能用内部资料拼接外发。用户选择渠道后按该渠道约束校验内容，变更内容后重做发送确认。
- P12/P13 对象不只是一段手填文本：真实流程必须解析可核验的渠道收件人并显示映射依据；同名不构成身份依据。填写收件人不会解除样例限制。
- P18 的客户数据导出/恢复与服务端灾备分开验收。恢复先展示客户空间、文件/版本、覆盖或合并范围、影响记录，再请求明确确认；权限校验在服务端，平台会话与凭据不进入普通导出。
