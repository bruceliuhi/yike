## 2. 产品到底卖什么

### 一句话定位

**意客AI是面向各行业企业的 AI 商机发现与跟进工作台：理解你卖什么，持续发现有依据的需求，帮助你判断、联系并跟进。**

付费价值假设是：减少搜索、翻评论、判断和联系准备的重复劳动，发现客户此前不知道且值得采取下一步行动的机会。是否实现该价值，必须通过真实使用、有效新增、沟通、成本和付费反馈验证；不是按采集条数、AI分数或页面数量证明。

### 谁使用、需要提供什么

- 使用者：有主动拓客需求的企业老板、销售、业务负责人及团队。产品支持跨行业业务画像，不以服务商、AI开发或展台行业作为准入限制。
- 输入：企业介绍、支持格式的产品/案例资料或公开网站；产品与服务、目标客户、地域、供应/交付能力、销售方式、交易规模/周期和排除项。
- 配置方式：AI先提取、建议，用户确认后执行；保留人工修改。行业模板是可选起点，不是行业白名单。
- 适用前提：目标买方存在可访问的公开业务信号，且至少有可行的后续联系路径。单一场景验证不代表所有行业效果相同。
- 暂不适合的期待：保证成交或固定商机量、无限触达、绕过平台限制、购买未公开联系方式、完全无人介入的成交代理。

产品通用、演示具体。宣传可分别选择制造/贸易、专业服务、软件/数字服务、本地生活、零售/品牌中已经实测的场景；不得把历史样例写成真实客户案例或全行业成功。

## 3. 用户完整流程与产品形态

```text
登录产品并连接平台
→ 提供资料，确认业务画像
→ 确认搜索方向、范围与预算
→ 多平台搜索与持续监控
→ 查看原文、时间、判断依据和未知项
→ 复核值得联系的机会
→ 编辑并确认对象、内容、渠道与连接身份
→ 实际执行、核对回执
→ 接收回复、安排下一步、记录效果
→ 根据反馈调整后续任务
```

八个一级入口：商机工作台、业务画像、线索采集、监控任务、商机库、触达中心、跟进记录、账号与授权。设计见 [R3 图册](../design/v02-suite-r3/README.md)，实际界面证据见 [UI 实施记录](UI_R3_IMPLEMENTATION.md)。设计完成不表示这些流程已经全部接通。

交付目标为 Windows 客户端与本机平台执行器，通过 HTTPS 连接服务端；正式客户数据使用私网 PostgreSQL。客户端不能持有数据库或管理员凭据，平台会话按客户、设备、平台和账号隔离。**本机离线时不能承诺继续采集**；云端调度存在也不等于云端平台执行可用。详见 [产品与开发权威](../AUTHORITY.md)。

### 平台能力不能用一个“支持”概括

首发建议组合为小红书、抖音、B站、知乎和公开网站/社区。采购公告、企业动态和行业网站按业务评估；微博、贴吧、快手、公众号、视频号属于扩展评估清单，不因写入列表即成为支持能力。详见 [多平台方案](V02_MULTIPLATFORM_SKILL_PLAN.md) 和 [任务书](V02_IMPLEMENTATION_TASKBOOK.md)。

每次对外列平台，必须分别核对：**可搜索、可读主帖、可读评论及上下文、可增量监控、可发送评论、可发私信、可接收回复**，以及账号权限、运行环境、已验收版本和已知限制。读取能力不证明发送能力，源码商业授权不替代通道验证；限流、验证和权限不足应暂停相应动作并明确提示。

2026-09-09用户最新调整开发顺序为**端到端体验＋少数强亮点**：首个可面向客户试用的版本必须完成真实发现→判断→确认联系→跟进，并同时保留**原文证据（PH-F06）、“多找类似”（PH-F11）和短句建联（PH-F13）**。原文证据不是可选详情或仅有AI摘要；需能回查来源、摘录、上下文、时间/版本和判断引用，反证、未知及访问失败如实呈现。“多找类似”须确认范围与用量后真实执行、去重显示新结果；短句须引用真实上下文、允许编辑并经最终确认后才能发送。

先把至少一个真实业务从输入贯通到跟进，不等高级管理全部完成；高级管理、复杂统计和自动更新后排，基础账号/数据保护、确认与防重复、真实回执/跟进、必要用量限制及可安装/恢复体验随闭环交付。更多需求类型、覆盖深度与自动化按后续阶段扩展；必要的未执行/失败/无合格结果区分不延后。V1.1重点是来源效果积累、自动扩展/预算优化、可靠跨来源关联和日常通知；不提前建设复杂学习系统。完整目标保留，试用里程碑不冒充完整商用验收；任务顺序和Win/Mac边界见[实施任务书](V02_IMPLEMENTATION_TASKBOOK.md)与[功能交接](handoffs/V1_WIN_FUNCTION_OWNERSHIP_20260909.md)。

### V1.0 搜索透明度必需项

“没有新线索”至少拆成：

1. 平台访问/连接失败，没有完成相应搜索。
2. 预算耗尽或范围尚未检查，当前结果不完整。
3. 已找到内容，但属于重复、过期、不匹配或无法核验。
4. 在**本次已成功检查的范围内**没有合格机会。

显示实际检查的平台、方向、独立来源、排除原因及未覆盖范围；按平台分别报告，不能用一个失败平台替代其他平台结果，也不能声称搜索穷尽全网。该项归入 F03/F04/F05，工程关联 V02-02、03、05。

### 增量验收看结果，不只看按钮

- 扩展搜索：相同预算下，去重后用户认可的新机会是否增加；是否过度集中单一作者；披露未成功访问的范围。
- 变化雷达：明确需求与推测分开，抽查反例；作者之外的第三方新评论不自动刷新原需求有效期。
- 建联教练：草稿引用真实、上下文具体、不虚构；比较同类线索的准备时间及实质回复，不为实验重复联系同一人。
- 时间线：能回查变化前后版本；不按相似昵称猜身份，不共享其他客户的私有沟通或结果。
- 补证：预算有实际约束，证据足够可停止，失败和成本可解释；未知成本不能计为零。
- 简报：所列机会和待办可回到真实记录；通知我们的付费客户与向潜客发消息是两个不同动作。

这些是待验证标准，不是已取得的效果。持续学习需要保存可追溯的来源、查询、画像/规则版本、成本与真实反馈，并遵守客户空间隔离；不能把私密客户内容直接汇入全局训练或共享线索池。

| V1增量 | 已获产品方向与版本划分批准，编入本手册 | 不称新增六项已开发或已发布；主线任务映射与实施分别追踪 | 本手册第5节、[产品计划](V02_COMMERCIAL_RELEASE_PLAN.md)、[任务书](V02_IMPLEMENTATION_TASKBOOK.md) |

### 完成状态的读取方法

不要改写任务书的 `NOT_STARTED` / `IN_PROGRESS` / `READY_FOR_REVIEW` / `DONE` 等状态。宣传判断另外检查证据层级：

- **规划**：有功能定义和版本目标，尚不证明实现。
- **开发中**：有实际实现，不能用草稿、页面或分支存在代替验收。
- **代码验证**：特定提交通过检查，仅能陈述对应模块和环境。
- **真实验收**：在明确平台、账号权限和环境走通实际流程；不自动证明商业效果。
- **已发布交付**：有发行/部署版本、支持范围、交付验收和已知限制；才能据此承诺对应可交付能力。

任务 `DONE` 必须看它是“纯契约子卡”还是“完整产品”：一个子卡的 DONE 不能升级成整个平台或产品已发布。自报联系、已核实发送、实际回复、报价和付款也不能相互替代。

## 8. 演示、报价与商业验证

### 三个演示时刻

1. **客户自己的资料**：从空空间确认画像、策略和任务，实际取回可打开的来源；不同业务使用不同条件，不能只替换行业名称。
2. **第二次运行**：只展示新增或实质变化，区分无新增、未执行和失败；解释为何值得联系。
3. **实际行动**：从可回查来源确定已授权验收对象，确认草稿后真实发送，回复回到正确机会；测试账号明确标识，不算商业转化。

真实演示素材必须标明对应提交/发行版本、日期、平台/权限、输入、结果及限制；发布前检查商业保密和个人信息授权。Cookie、Token、Profile、二维码、未公开联系方式、无关私信及客户秘密不得进入手册或截图。

### 报价之前先明确交付范围

现行计划允许按“软件试用/使用许可＋任务配置与上线辅导＋明确范围支持”开展验证。**本手册不设新价格、套餐、独享线索或数量保底承诺**。报价应列明已验证来源和通道、账号/设备、运行与模型用量、支持周期、外部成本、运行环境和验收方式。

版本验收仍遵循 [产品计划](V02_COMMERCIAL_RELEASE_PLAN.md) 的 M1/M2/M3、CP-06与客户验证要求。首发既定代表性抽样为五类业务各至少两家独立企业、各14天；配置、同质量耗时、证据可追溯和可靠性交付目标均是**待验证指标**，未达到不能用手册更新来豁免。完整获客版不能被中间里程碑替代。

商业复盘分别记录：此前未知且客户认可的可行动机会、人工与软件辅助耗时、实际联系/实质回复/下一步、运行成本与干预、实付及持续使用/续费意向。没有回复、未付费和流失样本保留；不以功能测试通过宣布商业成功。

## 9. 谁维护、何时更新

### 单一事实来源

- 产品范围与交付约定维护在产品计划；执行状态、负责人、提交及接收记录维护在任务书。
