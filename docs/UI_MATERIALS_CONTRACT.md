# P03/P04 资料生命周期接入契约

本文件补充 [R3 页面契约](UI_R3_PAGE_CONTRACTS.md) 的 P03/P04，不改变已确认图册。界面保留资料列表、添加/编辑抽屉、上传文件/粘贴文字、用途和引用范围。新增的状态面板对应 [页面状态矩阵](../design/v02-suite-r3/PAGE_STATE_MATRIX.md) 要求的解析待确认、失败、移除和引用撤销。

## 当前实现与服务边界

画像列表、保存与确认沿用现有 JSON facade。确认画像仍只复用对应研究任务，不启动采集。没有资料服务时，现有添加、编辑、删除和 TXT/Markdown 读取继续保存为**本机会话草稿**；不报告上传、解析或对外引用成功。

`YikeService.materials` 是可选的 [MaterialService](../desktop/src/renderer/services/materials.ts)。只有存在该服务、已登录、且当前画像已有服务端版本 ID 时，页面启用客户空间资料生命周期。本轮没有新增资料 HTTP API、数据库表、AI 解析器、正式桌面 IPC 或默认模拟实现。生产适配器仍不提供此服务。自动化测试中的 `TEST` 数据只用于隔离验证。

客户空间资料与旧本机草稿使用不同存储语义；启用资料服务不会自动上传、合并或删除旧本机草稿。保存首个画像后仍展示可展开的本机草稿表，保留编辑和删除入口。“带入当前画像”只预填客户资料编辑窗，人工保存后才调用资料服务；取消不写入，原本机草稿保留，引用范围不提升，也不自动解析或确认。同一本机草稿带入同一客户空间与画像时，目标 materialId 固定为 `local-` 加 SHA-256 十六进制摘要；摘要输入为版本标识 `local-material-v1`、用户 ID、可信空间 ID/版本、画像版本 ID、本机草稿 ID 的 JSON 数组。ID 仅用于避免重复创建，不替代服务端权限。列表已有同 ID 时打开编辑并携带该记录的 expectedVersion；资料解析中、读取失败或有待核对操作时不能带入。不同画像/空间的目标身份分别计算；服务端仍须原子核对 ID 唯一性与 expectedVersion，不能无条件覆盖。

当前“用于画像”是**经人工核对后复制所选字段到本机画像草稿**，不新增持久引用关系、不自动保存或确认画像。现有画像 API 不接收资料引用 ID；服务端的正式引用追踪须在后续接入时补齐，不能宣称当前复制行为可被远程撤销或自动回溯。

## 数据与方法

可执行字段定义和校验见 [domain/materials.ts](../desktop/src/renderer/domain/materials.ts)，不要另外维护不一致的 DTO。

| 对象/方法 | 约定 |
|---|---|
| `MaterialInput` | `name` 1–100 字，`text` 1–2000 字且无 NUL；`purpose` 为产品介绍/真实案例/服务说明；`visibility` 为 internal/external；可选原文件名及字节数 |
| `Material` | 资料 ID、`profileVersionId`、正整数 `version`、更新时间和状态；同画像列表 ID 不重复；不得返回其他画像的资料 |
| `extraction` | 提取 ID、对应资料版本、五个画像字段的非空子集、各字段对应原文摘录；每项摘录必须实际存在于该版资料正文中；READY/REVIEW_REQUIRED 必须有证据 |
| `list(profileVersionId)` | 返回当前身份可见的该画像资料。加载、失败、重试、成功空集合分别呈现；错误不能显示为“暂无资料” |
| `mutate(request, options)` | 见下表。`options.signal` 控制请求等待；`onUploadProgress` 仅报告实际传输进度，页面不模拟百分比 |
| `operation(profileVersionId, requestId)` | 查询原操作的稳定回执，不重新执行写操作。必须验证当前身份，不能凭 requestId 越权读取 |
| `impact(profileVersionId, materialId, version, action)` | 返回同一画像/资料/版本/操作的引用影响、有效期和短期确认 token；引用项目区分画像与联系草稿 |

本期文件入口仅支持 TXT/Markdown，最多 200 KB、正文最多 2000 字。浏览器读取不是服务端上传；同步发送的是用户核实后的文字及文件元数据，不是原文件归档。切换到粘贴文字、重选文件、退出或 30 秒读取超时会使旧读取结果失效。

每次写入的 `MaterialRequest` 都包含 UUID `requestId`、固定 `profileVersionId` 与 `change`。服务端必须从真实身份解析租户和用户，不接受前端指定租户。下列校验、幂等和引用范围必须在服务端再次执行，不能仅依赖 UI。

| change.kind | 请求内容 | 成功回执要求与界面动作 |
|---|---|---|
| save | 资料 ID、`expectedVersion`（新增为 null）、完整 input | 返回更高版本 DRAFT；保存不是解析完成；修改已确认资料需要重新解析与确认 |
| parse | 资料 ID、期望版本 | 返回更高版本 PARSING / REVIEW_REQUIRED / FAILED；PARSING 仅表示解析请求已受理，用户刷新查询结果 |
| confirm | 资料 ID、期望版本、提取 ID、用户核对并编辑的字段子集 | 返回更高版本 READY，证据重新绑定返回版本；不得更换原文或静默采用其他提取结果 |
| remove | 资料 ID、期望版本、影响确认 token | 回执确认移除才从列表移除；历史资料与审计保留由服务端执行 |
| revoke | 资料 ID、期望版本、影响确认 token | 返回更高版本 REVOKED；禁止后续引用，不能声称撤回已发送内容或删除已复制的画像文字 |

每次资料状态写入递增资料版本，操作回执应返回**该操作产生的版本**，不能返回并发修改后的最新记录冒充原操作结果。直接写入成功路径还精确比对保存的正文/名称/用途/范围/文件元数据，或确认的提取 ID 与人工字段子集；内容不符保留输入和原请求。重开后的 `operation()` 不在本机保存正文快照，服务端必须返回原 requestId 对应的权威操作结果，不可返回其他写入版本冒充。AI 提取异步完成也须更新列表中的资料版本；人工确认对该最新版本进行乐观并发校验。确认提取只允许字段子集和原文核实后的编辑值，不允许无证据增加新字段。后端应记录原始建议、人工采用值、确认人和时间。

## 结果未知、取消与重复保护

回执必须准确绑定 `requestId / profileVersionId / materialId / kind`，状态为 SUCCEEDED、FAILED、PENDING、UNKNOWN。除移除外的成功必须含匹配资料且版本递增；FAILED 只有 `confirmedNoChange: true` 才能解除保护。网络错误、超时、无回执、回执错配和状态不完整均保留原请求。

提交前将**不含正文、名称、凭据或确认 token 的操作标识**写入本机持久记录，按用户与画像隔离；不可写或损坏则阻止新写入。该记录不属于“清空本机草稿”，退出或重启后仍需要核对，避免未知操作重复提交。服务端必须实现同身份/同 requestId 幂等与 expectedVersion 原子检查；本机记录不能替代服务端并发控制，也不防止用户手工清除存储。

写入与核对均最多等待 30 秒。取消面板、离页或换账号不表示远端操作撤销；迟到结果不能填入新页面、恢复已清理的草稿或触发成功通知。未知结果通过“核对原资料操作”恢复；只有已确认终态释放保护。确认 token 仅在当前影响弹窗内使用，不写入操作记录。

移除/撤销前须重新读取引用影响，失败可重试；用户勾选影响确认且 token 未过期才可提交。服务端提交时须再核对资料版本、token 有效期和引用快照。正式引用服务应阻断后续生成引用，并使受影响的未发送草稿重新复核；历史发送事实保留。

## 人工字段与引用范围

默认 internal，只用于内部画像判断。external 是用户选择的期望范围，只有真实服务返回 READY 才显示“允许对外引用”；本机草稿、DRAFT、解析中和提取待确认均不能用于外发。REVOKED 显示已停止引用。后续联系生成/发送服务必须检查该范围、当前版本及撤销状态。

核对提取面板显示原文及逐字段证据，可勾选采用字段、手工编辑，再确认。READY 资料仍需单独选择“用于画像”、核对当前人工字段并勾选替换确认；只覆盖所选字段，其他人工字段保留。核对期间画像变化会阻止覆盖，需关闭重开。复制后的画像保持未保存/未确认，旧任务仍绑定旧画像版本。
