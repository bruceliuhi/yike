## 身份与快照

正式解析位于 [opportunityResearch.ts](../desktop/src/renderer/domain/opportunityResearch.ts)。绑定包含 `userId / opportunityId / profileVersionId / sourceUrl / evidenceVersion`；必须由可信的当前会话提供 `accountScope` 并精确匹配空间 ID 与正安全整数版本；缺失或格式不合法时不调用 R4 新服务，不能从回包补出会话空间，也不能以用户 ID 替代空间授权。旧商机 facade 保留可用，R4 时间线与类似建议明确不可用。三类快照均要求 `generatedAt < expiresAt`，过期结果拒绝，生成时间最多允许领先本机 5 分钟以容纳时钟偏差。字段格式严格解析，不能用另一用户、空间、画像或来源版本的快照覆盖当前页面。

服务端从认证会话派生租户权限；这些前端字段只用于对账，不构成客户端选择租户的授权。响应应原子读取同一授权快照，携带 `snapshotId / generatedAt / expiresAt`。列表最多 1,000 条，必须是该授权范围的完整集合；超出能力返回明确错误，不能默默截断再宣称没有观察项。客户端只对该快照筛选、分页和统计，单次只展示 10 行。

P11 客户详情在新服务存在且会话空间已核验时从该授权集合精确定位 ID，避免观察项被错误映射为旧 facade 的其他客户；找不到明确报错。缺新服务或可信会话空间时继续使用已有单商机 facade，并核验返回 ID、排除样例伪装。

## P10：分类、复核与阶段分别保存

| 维度                 | 字段与规则                                                                                |
| -------------------- | ----------------------------------------------------------------------------------------- |
| 研究类别             | `OPPORTUNITY / OBSERVATION / EXCLUDED / UNASSESSED`；对应明确需求、观察池、已排除、待分类 |
| 需求/变化类型        | 服务给出 `type` 与 `reason`，不从标题关键词推断                                           |
| 分类证据             | `ruleVersion`、来源 URL、证据版本和原文摘录；非待分类项必须有当前原文中存在的引用         |
| 人工复核             | `PENDING / RECOGNIZED / NEEDS_EVIDENCE`；已认可需有复核人和时间                           |
| 原处理状态与采购阶段 | 继续使用 `intentStatus` 及既有 `libraryFacts`，不改名冒充分类                             |

同一画像内相同来源不可重复计入两个集合。来源以平台及外部帖子/评论身份区分，不按帖子URL合并不同评论。旧商机缺固定原文版本时保留UNASSESSED、空引用和缺口，允许省略sourceEvidenceVersion，不生成researchBinding；不能编一个版本以开启类似/时间线。旧已导入机会保留原tenant共享可见性，新原始候选/判断仍按owner私有，不借研究服务扩大读取权限。

引用可保留 `field`：`source.title / source.body / source.container_title / source.parent.body`。非正文引用必须与同版本 CAPTURED 快照对应字段一致，界面区分标题和上级评论上下文，不拼进买方正文。无结构化快照的候选只能引用可核对的正文；无法表达依据时保留待分类和缺口，不删除记录。

观察可来自明确业务变化，但不因此产生采购预算、联系人或近期采购意向。分类变更/观察升级/排除写入不属于本次新增只读服务；须先实现带来源版本、理由、人工确认和原请求幂等的正式写接口，不能用前端移动行模拟完成。

平台、类型、复核状态、关键词、原有阶段/截止、排序、分页及查看证据均可操作。客户导出仍排除公开样例，仅明确需求集合可批选；观察与排除不会通过导出按钮伪装为客户商机。公开样例的选择和客户导出禁用，右侧明确预算询价不等于已确认商机。

## P11：同来源版本链

`timeline(binding)` 返回同一来源的原文版本、变化、关联联系事件及证据缺口。版本需要稳定 ID、递增序号、前版本 ID、来源 URL、原文、发布时间、系统观察时间和访问状态。旧 V1 最后版本必须与机会当前证据版本一致；跨 URL 拼接、断链、重复 ID、反向变化或原文不存在的差异引用一律拒绝。V2 使用下述独立观察序列规则，不放宽 V1。

每条变化提供前后原文引用及版本，可表示原文、预算、截止或有原文依据的关闭。访问失败、验证码和 404 仅是访问状态，不能生成关闭事实。V1.0 不做跨来源、跨帖或同名实体合并。

人工联系和渠道事件分别标识：人工事件保留登记人，渠道事件必须有回执 ID；事件目标必须是当前机会。发布时间、事件时间、观察时间、记录时间分别显示，没有值显示待记录，不以当前时间补齐。人工登记不冒充渠道回流。

公开样例只展示原文首版、已有发布时间、无后续版本、未知实际采集留存时间和无客户联系记录；不调用客户时间线服务。项目变化标签为活动状态时展示该时间线。过期快照提示刷新。

### V2 留存观察与后续正文变化

2026-09-11 接续，[实施计划与限定验证](superpowers/plans/2026-09-11-source-content-changes.md#实施与验证)。按冻结 `observation.id`、本人 tenant/owner 与证据版本/时间/正文定位唯一 source；不按 PAGE 空外部 ID、同 URL 或实体名拼接。跨任务仅限本人同一 source。

`schemaVersion:2` 新增 `anchorObservationId` 与 `observations[{id,versionId,observedAt,receivedAt}]`。真实内容版本目录按首次观察排序；观察按 observedAt 排序，纳入锚点不必最后，A→B→A 保留两个内容版本、三次观察和两次变化。上限200观察/100版本，超限明确错误，不静默截断。

仅相邻、无歧义且纳入之后的正文逐字差异生成 CONTENT；元数据单独变化不生成正文提醒。同刻异文不能判方向，也不作下一次比较基点。每条新增前后 observation ID、`detectedAt`（两端 receivedAt 最大值），`occurredAt:null`；前后摘录必须逐字来自对应正文。旧观察晚上传不刷新原帖日期，不自动修改原人工判断、需求状态或发送资格。

页面标出纳入依据，按每次观察展示全文，分别显示发布时间、观察时间、收到时间及未知的实际编辑时间。该投影只描述已留存内容，不证明正在采购或覆盖全网。

## 多找类似：预览到本机草稿

`similar(binding, requestId)` 返回结构化、限时建议：建议 ID、原请求 ID、相似理由、引用证据、已确认画像 ID/版本、建议搜索词/排除词、实际支持平台、原范围/建议增量、认可记录和搜贝用量状态。只有真实、来源有效、画像已确认并经认可的机会才允许创建草稿。读取建议本身不执行。

用户可以编辑新增词、排除词、名称和平台，设置单次搜贝上限；来源数量和研究时长放在高级资源上限。硬上限规则不可取消。支持的平台来自服务能力，不硬编码成全部平台已接通；账号及能力在后续任务流程再次检查。50 搜贝不是这里的默认价格或套餐。

搜贝状态严格区分：`UNKNOWN` 显示暂不可计量；`ESTIMATED` 必须有非负数、搜贝单位、计量依据及时间；`METERED` 是已有计量记录，不能当作本次预测。修改配置使旧估算失效。搜贝上限留空可保留草稿，不能授权实际收费研究；启动需要新的可信计量及执行端强制上限支持。

创建前再次读取当前授权记录、画像与原请求建议，核验同一绑定、仍认可、建议语义未改变及平台仍支持。期间用户编辑、切身份/空间、版本更新、认可撤销或超时，均不创建草稿并保留输入；迟到结果不应用。

`SimilarResearchHandoff` 是显式同步本机回调，含固定 `requestId / draftId`、原机会/画像/证据绑定、建议 ID、用户最终词项/平台/范围、搜贝与高级硬上限。`createDraftFromResearch` 构建全新 TaskDraft，保留溯源；旧预估不是启动授权。

本机衔接由 `ResearchDraftHandoff` 执行：已有未保存任务先请求明确切换；保留旧任务到本机草稿列表，按固定新 ID 去重保存，然后打开 P06 条件步骤。取消不替换旧任务。它不调用任务启动、采集、写客户库或发送接口，故不存在服务端写入成功的推断；真实任务创建/启动及未知结果继续使用既有最终确认与原请求保护。
