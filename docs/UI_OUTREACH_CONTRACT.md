# P12/P13 触达队列与发送核对契约

此文记录 `codex/ui-interactions` 的前端交付范围。沿用已批准 R3 P12/P13 布局；生产队列、草稿生成/保存、渠道发送与回复回流服务尚未接通。新增类型和隔离测试不代表平台已经可用。

## 队列与对象身份

`YikeService.outreach?` 为可选服务组；缺失时显示“触达队列与发送结果核对服务尚未接通”，与成功返回零记录的空态区分。`queue('confirm'|'reply'|'issues')` 返回完整快照 `{queue,items,total}`。当前契约无分页；适配器不得悄悄截断快照。页面校验 total 等于条目数、队列一致、记录 ID 唯一、商机 ID/用途/正整数版本/更新时间有效、明确 sample 布尔值；无效响应进入可刷新的错误态。

- 待确认表示有待人工核对的联系准备记录；查看记录不构成发送确认。
- 待回复表示服务端归类的等待回复记录；页面不根据本机草稿猜测已发送。
- 需处理表示服务端归类的异常记录；展示返回的原因，不自动重发或登记已联系。

记录 `id` 与 `opportunityId` 独立。选中详情显示记录 ID、用途、版本、对象与全文；“查看联系准备”只按商机 ID 和 comment/dm 用途导航，重新读取商机，不把队列文字直接当已保存草稿。公开样例只能阅读；sample 标记或 sample 保留 ID 均阻止进入发送流程。服务端必须按认证租户过滤、授权读取并拒绝样例写入；前端检查不能替代此门禁。刷新、队列切换、退出或换用户立即移除旧数据。

## 生成与人工编辑

无评论或私信文字也展示“生成联系草稿”；生成失败可“重试生成”，空白/非字符串结果作为失败。所有生成先进入预览，只在用户显式“替换当前草稿”后改变本机文字；生成期间的人工修改保留并提示。切换用途不会把评论建议覆盖私信；离页后的旧生成结果不应用。

P11 可传 `#/outreach?opportunity=<id>&channel=comment|dm` 选择初始用途。路由没有自动生成副作用。保存失败保留输入；内容未保存不能准备发送。默认生产生成/保存方法继续明确 unavailable。

## 原请求发送与只读核对

新适配路径使用 `outreach.send(draft,{requestId,confirmationToken})`。页面先把用户隔离的 `[opportunityId,channel,version,requestId] → PENDING` 持久化，再发请求；持久化失败不得调用发送。ledger 只保存标识和状态，不保存全文、对象、账号凭据或 token，清草稿/退出不会移除它。

核对调用 `outreach.reconcile({requestId,opportunityId,channel,version})`，不调用 send，不生成新 requestId，也不重复提交。返回绑定必须逐项等于原请求；即使当前草稿已改版本，也查询旧请求并将其结果归于旧版本。

队列、生成、核验、发送与原请求查询的界面等待上限为 30 秒。超时不代表平台撤销了动作；发送已经开始时继续保留原请求保护，迟到响应不直接解锁，由原请求查询收敛结果。

| 回执 | 前端行为 |
| --- | --- |
| `SENT` 且 `confirmed:true` | 清原 pending，记录原版本 SENT，禁止该版本重复发送 |
| `FAILED` 且 `confirmed:true`、`confirmedNotDelivered:true` | 清原 pending、废弃确认 token 和勾选；用户必须重新核验并确认，才能以新请求发送 |
| `UNKNOWN` / `PENDING` | 保留原请求锁，允许再次只读核对 |
| 404、网络错误、未接服务、身份/版本不匹配、缺少确定字段 | 保留原请求锁，展示错误，不推断未送达 |

服务端须持久化 requestId 与发送全文/身份快照、执行幂等、禁止重复投递，核对回执只能来自实际渠道证据。确认 token 必须绑定服务器验证的来源、画像、账号、对象、全文和版本；新的 token 不得绕过同一商机/用途的未决请求。`FAILED` 不能仅表示请求超时或查无回执。当前前端本机保护不解决多设备恶意调用或服务端缺少幂等的问题。

兼容旧 `YikeService.send` 的结果判定保持既有行为，但旧二段 pending 没有原 requestId，不能猜一个查询编号或自动解锁。正式渠道接入必须实现上述可选服务组，不能只把旧 send 替换成真实发送。

## 验证与限制

UI 定向测试：`desktop/tests/ui/outreach-queues.test.tsx`、`outreach-reconciliation.test.tsx`，并回归原 `outreach.test.tsx`、`send-confirmation.test.tsx`。测试含三队列、读失败/刷新/空态、数据身份拒绝、样例、首次生成与编辑保护、原请求持久、确定成功/未送达、未知/错误不解锁、旧版本查询、清草稿与用户隔离。fixture 仅存在于 UI 测试与隔离视觉 harness，默认客户服务不注入测试记录。

这些证据证明前端契约与交互；真实渠道投递、回执对账、回复回流、真实租户鉴权、生产服务部署和 Windows 实机仍各按其门禁独立验收。
