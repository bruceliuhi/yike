## 2. 路由与组合方式

采用 hash 语义路径，适配受控桌面协议。`#Pxx` 只作为设计对照别名，映射到下列真实页面及局部状态；不得借别名注入已连接账号、运行记录或样例客户库。

| 页码 | 路由 / 局部状态 | 归属与复用 |
|---|---|---|
| P01 | `#/login` | 独立登录布局，不挂左导航 |
| P02 | `#/workbench` | 工作台；队列与初次引导是同一页的不同数据状态 |
| P03 | `#/profile?tab=business` | 业务画像模块的业务描述标签 |
| P04 | `#/profile?tab=materials` | 同模块资料标签；添加资料用局部抽屉 |
| P05 | `#/collection` | 采集任务列表，复用任务状态与操作组件 |
| P06 | `#/tasks/new?mode=once` | 一个任务编辑器的条件步骤；`step=connect` 是同组件第二步 |
| P07 | `#/candidates` | 候选列表加证据复核面板 |
| P08 | `#/monitors` | 监控列表，复用任务列表基础组件 |
| P09 | `#/monitors/:id` | 同一监控模块的详情与执行记录 |
| P10 | `#/opportunities` | 商机列表，客户与公开样例集合独立 |
| P11 | `#/opportunities/:id` | 商机详情；样例 ID 显式区分于服务端商机 ID |
| P12 | `#/outreach?opportunity=:id` | 草稿列表、编辑区、证据侧栏组成同一工作区 |
| P13 | `#/outreach?opportunity=:id&confirm=send` | P12 上的发送确认弹窗；保留草稿与来源参数 |
| P14 | `#/followups` | 跟进列表与关联回复分栏 |
| P15 | `#/followups?add=1` | P14 上的添加跟进抽屉，可保留关联商机上下文 |
| P16 | `#/connections` | 账号与授权模块的平台连接标签 |
| P17 | `#/connections?connect=platform&returnTo=...` | 平台登录弹窗；`platform` 替换为受支持平台键，返回地址仅允许内部路由 |
| P18 | `#/settings` | 账号与授权模块的设备与使用授权标签 |
| P19 | `#/tasks/new?mode=once&step=confirm` | 任务编辑器的只读确认步骤；持续任务保留 `mode=monitor` |
| P20 | `#/tasks/new?mode=monitor` | P06 条件步骤展开持续日程，不另建一套任务表单 |

主模块保持八个导航入口。抽屉、弹窗、标签和任务步骤由少量模块组合，不创建 20 个相互复制的全页组件。路由变化保留当前筛选、滚动、选中条目和未保存草稿；草稿记录与业务成功状态分开。内部 `returnTo` 不接受外部 URL，缺失时回对应模块。

## 4. 服务依赖与真实能力边界

页面通过类型化适配器读取数据及提交动作，不能在 JSX 中散落网络、IPC、模拟成功或数据库逻辑。下列名称是能力契约分组，不是已存在的 HTTP 接口名称。

| 服务组 | 必需能力与权威数据 | 当前接入前提 |
|---|---|---|
| Session | 客户登录/退出、当前身份、授权状态、验证码冷却 | 已接短期访问凭证交换与 Cookie 会话；手机验证码、试用开通和授权激活仍不可用，不借旧凭证接口伪造验证码成功 |
| Profile / Material | 画像版本、确认、业务资料、引用范围、提取结果确认 | 画像列表/保存/确认已接 JSON facade；资料当前为本机会话草稿，TXT/Markdown 读取不是上传客户服务，提取与外发引用仍待接入 |
| Discovery | 任务草稿、平台能力、搜索建议、候选、用户复核、启动/暂停/恢复、逐平台运行 | 已写类型契约与可用契约下的交互；实际 adapter 的候选/复核/任务/建议仍明确不可用。研究 Skill 文档不等于执行运行时 |
| Opportunity | 客户商机列表/详情、证据、来源状态、筛选/导出 | 已复用 PilotStore 并接 JSON facade；筛选/CSV 导出只操作当前获授权客户集合，样例独立只读 |
| Outreach | 分用途草稿、对象映射、版本、发送确认、发送/回执/回复 | 已有前端确认状态；真实生成、保存、核验、发送与回复服务仍不可用。确认 token 和未知结果的接入门禁见 5.3 |
| Followup | 人工事实、真实回复关联、负责人、下次跟进、纠正记录 | 人工事实保存/读取已接 facade；当前服务只接商机、状态、备注。联系时间/下一步可写备注，结构化提醒、负责人分配、纠正链与回复回流未接入 |
| Connection / Desktop | 本机状态、原生登录窗口、检查连接、设备/授权、更新、导出/恢复、脱敏诊断、受控外链与剪贴板 | 桌面桥已提供运行状态、真实版本/系统、白名单 API、受控外链与剪贴板；平台登录/执行设备运行时、激活/更新与客户恢复仍不可用 |

当前源码入口是 [renderer 服务接口](../desktop/src/renderer/services/contracts.ts)、[默认适配器](../desktop/src/renderer/services/client.ts)、[桌面白名单](../desktop/src/main/servicePolicy.ts)、[服务客户端](../desktop/src/main/serviceClient.ts) 和 [JSON facade](../pilot/ui_api.py)。桌面 CSP 的 `connect-src 'none'` 保持，renderer 不直连服务或 PostgreSQL。主进程仅接受本窗口主 frame 的固定 IPC 操作，固定 `YIKE_SERVICE_URL`；发布包仅 HTTPS，开发回环 HTTP 需显式开关。主进程为这些白名单请求附固定服务 Origin，禁止重定向与任意请求头/URL。

应用 Cookie 不由 renderer 读取。当前应用会话放在非持久 Electron session 中，登录/退出请求串行，退出时清本机 Cookie；即使远端注销失败，也须核对本机身份后退出，并保留“服务端注销尚未确认”的提示。访问凭证、确认 token 和数据库凭据不得写入本机业务草稿、诊断文本或导出物。

实际 `/api/ui` 已接入：`GET/POST/DELETE /session`，`GET/POST /profiles`，`POST /profiles/{version_id}/confirm`，`GET /opportunities`、`GET /opportunities/{id}`，`GET/POST /followups` 和 `GET /capabilities`。租户、用户、复核权限由服务端身份解析，不接受客户端指定租户。画像确认复用原有 `research:{version_id}` 研究任务；它不是 P19 的多平台采集启动。

本地隔离 PostgreSQL 16 与实际 facade 的 [22 项检查](qa/ui-r3/postgres-api-check.json) 已记录凭证会话、画像与研究任务幂等、商机与跟进租户隔离、非超级用户/RLS、Origin 拒绝、注销及缺发送能力。该证据使用隔离合成数据，不证明平台收发、生产 CP-06 或 Windows 安装通过。

共用数据状态至少区分 `loading`、`ready`、`empty`、`unavailable`、`error`、`unauthorized`；只有真实读取成功且集合为空才显示业务空态，服务未接入不能显示“暂无新增”或“已连接”。公开样例为显式只读集合，与客户数据在身份、缓存、选择集、写入和导出路径隔离。

## 5. 20 页动作、缺失状态与验收

这里的“验收”是应执行的检查，不代表已执行。正常、错误和缺能力状态复用共享组件，无需为每个错误另画一张设计图。

| 页面 | 主动作与服务依赖 | 必须补齐的状态 / 最小验收 |
|---|---|---|
| P01 | 登录 → Session → P02 | 验证码发送/冷却/错误/过期、网络失败、授权未激活；错误保留非敏感输入；无认证服务时不进入假登录成功 |
| P02 | 新建 → Discovery；引导读 Profile/Connection，待办读真实队列 | 初次使用、已有队列、读取失败/未接入、离线、今日为空分开；点击四个队列到对应范围；样例不计入任何客户统计 |
| P03 | 保存/确认 → Profile；确认后进入任务 | 必填校验、保存失败、已确认版本变更、确认摘要、未保存退出；失败不丢表单，不把编辑内容自动标为已确认 |
| P04 | 添加/保存 → Material | 上传进度、类型/大小限制、失败、提取待确认、删除/撤销引用；限制来自服务契约；内部资料不能被外发草稿引用 |
| P05 | 新建/编辑任务 → Discovery | 空列表、运行/取消中、受限、失败、完成无结果；行操作绑定正确任务；配置草稿不展示真实运行次数 |
| P06 | 下一步连接 → Discovery/Profile/Connection；保存草稿 | 初次建议、生成中/失败、人工编辑、重生成预览、过期响应、冲突词、缺画像/连接；保存和下一步使用同一草稿版本；第二步为每个平台选择账号/能力 |
| P07 | 确认入库/排除 → Discovery 复核 | 原文失效、缺画像、重复、重新判断、写入失败；真实候选展示匹配/行动/价值/风险/未知项；公开样例即使选中也不能确认或批量入库 |
| P08 | 新建监控 → P20；暂停/恢复 → Discovery | 运行/暂停/待配置/离线/需处理；恢复先展示对象与影响；上次时间由实际运行生成；未执行不能写“无新增” |
| P09 | 重新连接 → Connection；重试/取消 → Discovery | 逐平台无新增/成功/失效/受限/失败/离线及部分完成；只重试正确范围；无运行数据的图中状态示意不作为生产默认记录 |
| P10 | 查看证据 → Opportunity；导出选中客户商机 | 真空库/筛选无结果、失败、分页、无权限、导出中/失败；返回详情保留筛选与页码；筛选后总数来自同一集合；样例始终不可导出为客户商机 |
| P11 | 查看来源/复制 → Desktop；真实商机进入 P12/P15 | 来源失效/受阻、历史画像、关闭/排除、无渠道；复制可验证剪贴板且不产生发送记录；原文缺失明确展示，不能拼造 URL；需求概述按设计勘误与真实来源字段 |
| P12 | 保存草稿/准备发送 → Outreach | 无草稿、生成失败、人工编辑未保存、账号失效、对象无法映射、发送中/失败/未知；重生成先确认，保存内容与预览全文一致；样例的编辑/生成/保存/备注写入禁用，仅查看与复制 |
| P13 | 确认并发送 → Outreach + Connection | 校验已入库真实商机、映射对象、账号、内容版本、用户勾选；任一变化废弃确认；重复提交防重；未知结果查询原请求；样例填完所有字段仍不可发送 |
| P14 | 添加跟进 → P15；查看关联回复 → Followup/Outreach | 空列表、未匹配回复、未读/已读、到期、加载失败；人工/通道事实显式分开；选择条目后右栏关联正确客户与发送记录 |
| P15 | 保存记录 → Followup | 只关联已入库商机，校验事实类型/实际时间/必要字段；失败保留输入；取消恢复焦点；人工记录不得标记成通道回执；纠正保留审计 |
| P16 | 添加/连接 → Connection | 未连接、连接中、已连接、失效、受限、断开；按平台能力展示；断开确认说明影响任务；公开网站范围待确认不变成无限制读取 |
| P17 | 打开原生登录窗口，随后检查 → Desktop/Connection | 等待/取消/超时/连接失败、登录成功但能力不足；不伪造二维码，不收平台密码；完成返回原任务同一步和同一草稿，不自动启动采集 |
| P18 | 激活 → Session/Desktop；绑定/更新/恢复等受控操作 | 激活失败/过期、设备撤销、下载失败/回退、恢复目标/覆盖确认、诊断脱敏；缺桌面桥时明确不可用；恢复只操作本客户授权数据，不恢复整个服务端数据库 |
| P19 | 确认启动 → Discovery | 使用已保存最终条件；摘要含画像版本、词项、来源、账号、设备及监控日程；缺项阻止启动；重复点击只对应一个请求；未知查询原任务；不得重新调用建议覆盖人工词 |
| P20 | 下一步连接 → 与 P06 同一任务编辑器 | 每日多时刻/间隔与起止窗口、时区、跨日、重复时刻、平台频率限制、离线；09:00/15:00 仅示例可编辑，可增删；重生成搜索条件不能改变日程 |

搜索条件的人工词保护、删除不复活、过期响应处理及最终配置快照严格沿用 AI_SEARCH_CONDITIONS。关键词的执行语义、排除匹配字段、离线错过时刻的处理、运行重叠以及待联系/待回复队列转换规则须由对应服务契约明确；前端可先做控件和状态，但不能自行猜测规则后开启真实采集或发送。

### 5.1 P07 候选判断与人工复核

类型与规则以 [domain/candidates.ts](../desktop/src/renderer/domain/candidates.ts) 为准。`candidates(query)` 返回 `{items,total,page,pageSize}`，查询支持文字、平台、状态和分页；`ids + reviewRequestId` 只读核对原请求。`reviewCandidate(review)` 区分 `ASSESS`、`INCLUDE`、`EXCLUDE`。这两个方法当前没有 HTTP/IPC 实现，默认返回 `CAPABILITY_UNAVAILABLE`；组件测试服务替身不进入客户运行路径。

- 候选绑定 `id/revision/sourceId/sourceVersionId/sourceStatus`，并保留完整原始摘录、URL 和原始来源。`sample=true` 或保留样例 ID 只读；客户列表收到样例也拒绝混入。
- `ASSESS` 必须绑定已确认的画像 ID/版本与候选/来源版本，返回匹配理由、行动信号、价值判断、风险、未知项五项建议；建议不是入库审批。过期响应拒绝，人工修改需确认才可用新判断覆盖；请求失败保留旧文字。
- `INCLUDE/EXCLUDE` 的确认摘要固定五项人工依据、画像/来源/候选版本、判断 ID、请求 ID；需要显式人工勾选，排除另需原因。样例、已处理候选、未知请求、缺证据或旧判断均不能提交；来源非 `OPEN` 阻止入库，打开原文不会自动解除。
- 最终回执必须同时有服务端复核人/时间、同一请求与动作、正确候选状态、实际商机 ID（入库时），并包含与人工确认全文一致的 `review` 快照。缺项、相互矛盾或替换人工内容均视为未知，不显示成功。重复来源只接受 `ALREADY_IMPORTED` 与已有商机，不创建第二条记录。
- 每次提交先保存请求状态；超时/网络错误/处理中的结果禁止直接重提，必须按原 `reviewRequestId` 查询。批量操作逐条展示、逐条提交；首个未知/失败立即停止后续，说明此前完成数。服务端须持久化请求幂等和回执、重验租户/画像/来源版本，不能依赖页面内状态抵挡并发或重登。

### 5.2 P09 监控详情与操作范围

[TaskRun 类型](../desktop/src/renderer/domain/models.ts) 在任务基础字段外提供画像/版本、关键词/区域、创建时间、日程、最近/下次运行、失败原因，以及 `platformStages`、`events`、`statistics`。可选字段缺失显示待读取或 `—`，不补造时间、账号、次数或零新增。

平台面板逐项区分等待、运行、成功、明确无新增、登录失效、限流、失败、离线、暂停、取消、需处理和重试。只有服务明确 `NO_NEW` 才能说本次没有新增；成功但未返回数量时仍显示 `—`。执行记录逐条保留服务事件 ID、时间、平台、正文和级别，配置标签显示服务持有的画像版本、范围及日程。

当前 `taskAction(id,action)` 作用于整个任务，不提供平台子任务参数；平台错误旁按钮也明确为“重试任务”，弹窗说明实际失败阶段与重试范围由执行服务确认。登录失效只导航到对应平台连接，并携带原监控详情 `returnTo`。暂停/恢复/重试/取消先显示任务与影响，提交后重新读取服务状态，不在本机直接把任务标成已暂停或已完成。未来增加单平台重试须先扩展有明确范围与幂等语义的服务契约。

### 5.3 P13 对象核验、确认 token 与未知发送

`verifyContact(draft,fingerprint)` 返回 `ContactVerification`：`allowed/fingerprint/confirmationToken/expiresAt/opportunityId/accountId/channel/recipientId/recipientLabel/reason`。`send(draft,confirmationToken)` 是独立动作，当前返回契约仅 `{status:string}`；两者默认均不可用。核验本身不能发送，也不能把手填收件名称当成渠道身份。

确认窗口保存当前全文快照。指纹绑定商机、画像版本/状态、来源状态、是否样例、评论/私信用途、草稿版本/全文/已保存全文、发送账号、手填对象、连接状态和能力。先核验服务映射出的真实对象，展示其名称，再让用户勾选；发送前再次核验相同快照，对象 ID/名称、内容、账号、来源或身份变化均取消确认。token 到期取消勾选；token 仅在组件内存使用，不写本机草稿。

发送前记录待定尝试；只有服务 `SENT` 才显示渠道确认成功，其他状态及不确定网络结果保持待核对，不能一键重发。防重记录与可清除业务草稿分离，至少按用户、商机、用途与版本隔离，不能因返回修改、离页或清草稿解除。该本机保护不是服务端幂等证据。

**真实发送接入门禁：**服务端必须重验客户已入库且未被撤回的商机、实际来源版本、画像、渠道映射对象、账号权限和全文版本；生成短期、不透明、绑定这些服务端事实的确认 token。token 的刷新/二次核验必须关联同一持久发送操作，不能借新 token 绕过上次未知结果而重复发送。发送与回执保存须支持幂等并返回可核对的渠道证据。当前服务接口尚无发送操作查询方法，页面只能保守锁定并提示核对；启用真实通道前必须补“按原操作查询/确定失败后重试”契约与 UI，不能把现在的 `status` 或本机 ledger 当成完整回执对账。

### 5.4 P19 启动结果与 P20 日程

P06/P20/P19 共用同一任务草稿，最终确认包含所有当前条件、画像版本、账号、设备与日程。启动前重新读取画像、连接与设备能力；确认后任何指纹变化都阻止启动，不重新生成建议覆盖人工词。请求键为 `task:{draft.id}:{draft.revision}`，发送前先记录，网络未知保留防重。

只有返回非空服务端任务 ID、合法状态、匹配的名称/运行方式/平台范围，以及一致的可选画像信息，才能清除未知记录和本机草稿库条目，并说“任务已创建”。空响应或其他配置的任务都保留未知状态；离页后迟到响应不得把用户导航回旧流程。后端仍须把请求键持久化并提供原请求对账，不能通过重新登录或复制草稿绕过未决启动。

日程界面可添加每日时刻（最多增至 6 个），校验时刻格式与重复；间隔输入校验 1–168 小时与有效起止窗口，并记录明确时区。跨日窗口、夏令时、错过时刻、运行重叠与平台限频的实际调度由后端契约定义并验证；页面配置成功不表示调度已经运行。

## 7. 交付验收顺序

1. 静态结构：20 个设计 ID 均定位到语义路由和共享模块；九张主页面的区块顺序、比例、导航高亮、主次按钮与表单标签一致。保留 P06/P20/P19 一份任务草稿。
2. 可交互验收：在真实 renderer 逐条点击主路径，验证返回保留状态、Tab/Enter/Esc、焦点恢复、错误重试和未保存退出。数据/动作尚不可用时给真实状态，不通过随机数据或成功 toast 充当接通。
3. 接口验收：已接接口用真实受认证响应；未接服务单独记录缺口。样例、跨客户数据、重复提交、过期响应、人工内容保护及发送确认必须有有效反例检查。
4. 视觉验收：按 `1440 × 1024` 同视口、同状态拍实际运行截图，与 R3 对应页并排检查；再验窄窗口、缩放、长标题、表格滚动、底部遮挡和正文/按钮对比度。截图检查由主开发任务执行，本预检未运行浏览器或 CUA。
5. 工程与发布分开：类型检查和 renderer 构建证明前端候选可构建；真实 Windows 安装/休眠/更新、平台账号与真实通道、HTTPS/服务端/数据库门禁仍按 V02 与 CP-06 验收。不得把可点击页面等同于完整可售版。
