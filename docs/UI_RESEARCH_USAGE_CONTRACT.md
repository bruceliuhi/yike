# R4 研究用量与搜贝合同

2026-09-09，用户要求用“搜贝”统一衡量研究用量，并授权其余 R4 图继续开发。本文属于既有 V0.2 的任务配置、执行和客户端子卡合同，不是新增版本或收费承诺。

2026-09-11确认版本增量：正式估算请求必须带`strategyBinding`（策略UUID、画像UUID、服务端configurationSha256），响应另含`ruleSha256`；本机configurationHash仅作编辑标识，不能代替服务端确认摘要。实际服务通过固定`researchUsage.quote`/`POST /api/ui/research-usage/quote`传输，先确认策略再估算。实现与限定证据见[实施记录](superpowers/plans/2026-09-11-confirmed-research-quote.md)；默认组装尚缺研究执行能力与获批规则，仍返回不可用，不代表已经能启动研究。

## 客户表达

- 任务显示预计消耗、最多使用、实际消耗；未估算显示待估算，未启动显示尚未启动，未知不显示为 0。
- 搜贝只衡量研究用量，不代表机会条数、采购金额或成交。机会原文中的采购预算及其变化仍用原单位表达。
- 来源条数、时长与模型调用上限归入高级设置；固定补证顺序及任一上限停止不可关闭。前端初始资源上限是可修改配置，设计中的 50 搜贝是配置示例。
- 未定义兑换比例、售价、充值、余额、赠送或退款政策。不得在客户端推导价格或虚构可用余额。

## 本次前端合同

`ResearchSettings` 随任务版本保存需求类型、搜贝上限、三项资源限制与补证顺序。相似研究另保存原机会、画像、证据、建议和账户空间来源。上述内容全部进入启动配置 hash；任一修改使旧估算和用户确认失效。未填完的合法表单值可以留在本机草稿，估算及启动必须通过严格配置验证。

`ResearchUsageService.quote` 只读取估算，不预留或扣减搜贝。响应须精确回显用户、可信账户空间/版本、请求 ID、草稿 ID/版本、配置 hash、上限，并携带 quoteId、计量规则版本、依据和有效期。估算超过上限、范围不匹配或过期一律拒绝使用。确认令牌只留在页面内存，不进入草稿、日志或未知结果账本。

新执行适配必须声明 `researchContractVersion=1`，在同一次幂等启动中原子验证 quote 与当前权限、预留上限并创建任务。旧执行器不能忽略新配置后返回成功；缺能力时可以编辑/保存草稿，不能启动 R4 研究任务。旧无 research 字段的历史草稿仍按旧能力校验，不伪称受到搜贝控制。

启动账本持久保存原请求/配置 hash/模式及不含令牌的预留摘要。`ACCEPTED` 必须回显同 quoteId、规则、上限和账户空间；`REJECTED` 还必须明确未创建任务、无剩余预留。回执不匹配、超时或 PENDING/UNKNOWN 保留保护，禁止重发新请求。恢复查询只允许在原客户空间进行。清空普通草稿不能清除这份账本。

任务草稿与草稿列表按 user + accountScope id/version 隔离；无空间字段的旧服务使用旧键。跨空间来源不能拿到新的有效估算。页面切换、退出、服务替换和配置变更使迟到响应失效。

## 服务端仍须交付的部分

实际资源事件应带任务、运行代次、请求和计量规则版本，按幂等键入账；结算不得超过预留，扩大上限必须新估算并由用户明确确认。暂停请求、实际暂停、结算中、已释放要分别表达；未知结果不能由前端猜测扣减或释放。需要实际数据库事务、并发、任务取消、超时重放、租户隔离及账目核对的服务端证据。

本次可选接口、客户端交互和隔离 TEST 验收不等于真实计量后台、售价或商用结算已完成。
