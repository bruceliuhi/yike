# 监控日程配置契约 v1

本契约属于已授权 P20 / P19 / P09 前端交付。它明确可保存、核对和传递的日程含义；当前没有新增调度器，不证明真实监控已按以下规则运行。

## 配置与兼容

`Schedule.policyVersion = 1` 纳入任务配置指纹、最终确认和启动绑定。新草稿使用 v1；未声明版本的历史草稿原样保留，不自动补值、不改写已有配置摘要。只有用户点击“采用当前日程规则”才换版，换版使原确认失效。

适配器通过 `taskOperations.scheduleContractVersion = 1` 声明完整支持后，才可派发 v1 监控。页面预检、启动时重新读取条件、最终派发前均核对声明。没有声明时仍能编辑和保存，不能以旧接口启动新规则。旧草稿仅走原有未版本化接口及其原有门禁，不将其标成 v1 已验证。

## 确切时间含义

- 所有本地日期和 HH:mm 使用配置中的 IANA 时区；设备当前时区不改变配置。时间格式、重复每日时刻、1–168 小时间隔由现有校验处理。
- 每日执行：按本地日历日期和所选时间生成计划。DST 导致某时刻不存在时跳过；重复时刻只采用较早的真实时间点。
- 间隔执行：每天以本地窗口开始时刻为锚点，之后每隔配置的实际小时数生成一次计划；窗口含开始、不含结束。结束早于开始表示次日结束，相同起止不解释为全天，要求修改。
- 间隔窗口的任一边界因 DST 不存在时，跳过该日整个窗口；边界重复时采用较早的真实时间点。解析后结束不晚于开始的窗口也跳过。间隔从该窗口的真实开始时间点计算，次日新窗口重新建立锚点，不将前一日余数带入。
- 创建或恢复在线均只等待其后的下一个计划时刻，不立即补跑错过的计划；关机、离线、权限不足不能计为“已搜索但无新增”。临界时刻的派发、防重、租约及取消仍由执行服务负责并返回可核对回执。
- 下一次实际运行时间只能来自执行服务。前端不计算一个时间冒充已安排；完整执行适配验收必须包含跨日、DST 跳变、重复时刻、离线恢复和相邻窗口。

示例：22:00 到次日 02:00、每 3 小时，在无时区跳变的一天生成 22:00、次日 01:00 两个计划；02:00 不包含在窗口内。23:00 恢复在线时不补 22:00，等待次日 01:00。

## 验收边界

前端回归涵盖历史草稿指纹不变、明确采用后指纹变化、往返步骤和保存、跨日说明、相同起止校验、适配器声明及延迟预检后声明撤回时不派发。DST 文案测试只证明配置说明，不等于真实时间调度测试。真实执行器须逐项实现上述规则再声明支持。
