## 1. 产品承诺与首发边界

意客AI是面向各行业企业的 AI 商机发现与跟进工作台：理解企业销售的产品或服务，持续发现值得联系的需求，说明判断依据，完成联系并跟进结果。首发不设置服务商或展台行业准入限制；展台保留为历史研究与测试样例。

首个完整付费版必须包含：软件登录与平台连接、任务配置、真实线索采集、增量监控、AI意向判断与证据、商机复核、真实触达执行、回复及跟进、可安装交付与支持。

现有实现是复用基础，不是产品功能上限。“人工导入研究包＋复制草稿”属于中间开发里程碑，不能作为这一完整获客版的最终交付或被改名替代缺失能力。

首发保留多平台采集与监控；具体建议清单为小红书、抖音、B站、知乎与公开网站/社区，逐平台完成真实运行验收。通用研究 Skill、行业/销售方式策略、平台 Skill、实际连接器和调度系统的分工见 [多平台 Skill 监控方案](V02_MULTIPLATFORM_SKILL_PLAN.md)。行业模板是可选起点，不是行业允许名单；不以单一模板或单一行业演示代替通用能力验收，也不能用单平台替代多平台交付。

针对不同业务评估采购公告、企业公开动态、行业网站等来源，记录是否纳入首发及其依据；它们不是仅添加一个“web”菜单就已支持的能力。企业可自主创建业务画像，但实际可读取、监控、触达和接收回复的范围分别说明与验收；没有适合来源或联系路径时如实反馈，不承诺全网覆盖或全行业同等效果。

用户已明确取得 MediaCrawler 商业授权，直接采用该代码复用路线；对外统一意客AI品牌，不展示内部引擎名称。技术记录保留依赖版本与溯源。

| 持续监控 | 一任务选多个平台，分别定时运行、维护游标和内容版本；上次/下次执行、暂停/恢复、独立重试、部分成功和新增/实质变化提醒；有证据的需求时效提醒 | 多个平台持续提供新发现；单平台受阻不拖停其他平台；重复不冒充新增，本地离线与连接失效分别显示，不编造截止时间 |

| 触达中心 | 结合原文与真实业务资料生成并保存独立草稿；确认对象、内容、渠道；通过真实适配器执行；发送状态、回执、失败原因、暂停、去重 | 从发现需求走到实际联系。复制功能可保留，但不等于发送；不确定发送结果不得盲目重试 |
| 回复与客户跟进 | 对已接通渠道接收并关联回复；未读/待跟进提醒、负责人、标签、备注、下一步时间；联系与回复时间线；真实新增商机、有效回复、后续动作及用量/成本反馈 | 减少遗漏并检验实际价值。通道事件和人工登记分别标识，不把发送成功当作客户回复；成本未知时标未知，统计可由明细复算 |
| 商业交付 | Windows 安装/卸载、激活与试用有效期、更新与版本回退、凭据私有存储、备份恢复、数据导出、支持入口与可脱敏诊断 | 客户能安装、持续使用和处理故障。发行包、渠道稳定性与售后共同构成可交付产品 |

所有价值是待验证假设，不是既有业绩。第一版可以不支持高级团队权限、充值商城、代理商系统、完整 CRM 合同财务，但基础使用授权、客户空间隔离和数据恢复必须可用。

## 3. 最有说服力的三个演示时刻

1. 客户提交自己的企业介绍、公开网站或支持格式的资料，确认“卖什么、卖给谁、覆盖哪里”；系统形成可编辑画像与行业策略。确认任务后实际搜索并带回可打开的需求原文；使用差异较大的企业展示策略如何变化。没有符合结果时，说明没有结果并给出可修改的条件，不填充假商机。
2. 查看同一任务的两个真实运行批次：第二次只推送新增或实质变化；打开一条线索看到命中证据、排除原因和建议动作。展示系统为什么值得持续使用。
3. 审核针对某条需求的草稿，向明确授权的验收对象实际发送，显示真实状态；收到测试回复后回到同一商机的跟进时间线。测试账号明确标识，不能作为客户转化业绩。

静态公开询价样例继续用于讲清证据结构，不再承担整套获客软件的主要销售演示。当前整套设计已覆盖“获客任务创建/执行”“新增线索与意向复核”“触达与回复跟进”，以及登录、资料、平台连接和设备授权；保持既定蓝白视觉体系。设计图用于选择界面，实际销售演示仍须完成上述真实流程。

## 4. 导航与页面组织

保留目前八个一级入口：商机工作台、业务画像、线索采集、监控任务、商机库、触达中心、跟进记录、账号与授权。

- 获客任务创建与模板作为线索采集的主入口，单次运行结果可转为持续监控；选定业务画像后自动准备可编辑搜索条件，重新生成不覆盖人工修改。具体状态与验收见 [AI 搜索条件建议](../design/v02-suite-r3/AI_SEARCH_CONDITIONS.md)。
- 视频、作者、评论属于来源类型与筛选维度，不各建一套互不贯通的客户库。
- 资料与案例属于业务画像内的业务资料标签页；话术版本属于触达中心。
- 工作台突出真实待处理队列和“新建获客任务”入口；运行数量、线索数量和联系结果仅来自数据库。
- 每个页面围绕一个主要动作，详情、发送确认和任务配置渐进展开；功能丰富通过完整流程表达。

关键适配风险应提前验证：现有平台 browser profile 按平台固定，不能直接用于多客户；旧执行器存在 Unix 进程管理，Windows 支持不能仅放在最后套壳。真实发送通道与 Windows 执行可行性和首轮采集并行验证。

采集与触达之间必须保存来源用户标识、通道收件人标识、映射依据、可联系条件及不可联系原因；不能根据相似昵称猜测跨平台身份。整链验收采用明确授权且可从采集来源回查的对象，证明“采到的人”确实能在该通道联系并关联回复。

状态模型、字段和接口只放入明确模块：平台会话 / 采集适配 / 任务执行 / 意向处理 / 触达适配 / 跟进事件。保留现有 Web 路由薄层，不把全部逻辑追加到一个大文件。

## 6. 里程碑与发布规则

- M1：多平台连接＋逐平台真实首次采集＋原始结果，可内部演示；阶段性单平台贯通仅算子任务完成。
- M2：多平台持续监控＋Skill意向筛选＋用户复核＋统一商机工作台，可邀请客户检验线索价值。
- M3：真实触达＋回复回流＋跟进＋Windows交付＋独立验收；实际服务端交付通过 CP-06（含私有客户环境），形成首个完整付费版。

可按里程碑预览和修正，不将 M1/M2 宣布为用户所要求的完整获客版。任何首发必需能力遇到问题，都保留在交付清单并安排解决任务，不能默默删除后称已完成。若具体平台确实不支持某路径，记录事实与可行替代，经产品范围决策处理，而不是无限期“后续再说”。

研发可分批交付，但第一付费版的目标清单保持完整。源代码授权已经由用户确认，后续不重复索取。

M3 是技术交付门槛；共同首发 Goal 还须完成下节跨行业、体验和价值验证。某项未达标时保留缺口与下一动作，不默认豁免；若需要改变首发承诺，由用户明确决定。不得把任一平台/行业暂时受阻解释为可以静默缩回单行业产品。

## 7. 客户验证与收费方式

买单人假设：各行业企业中需要主动寻找需求、拓展客户或渠道的老板、销售及业务负责人。产品/服务、客户类型和销售方式决定适用策略，不以服务商身份筛选。现有展台资料仅作为历史样本，不能代替跨行业客户验证。

初期可采用“软件试用/使用许可＋任务配置与上线辅导＋明确范围的支持”交付，先人工开通和对公收款，不因缺充值商城延误验证。正式报价先列清来源、账号/设备、运行与模型用量、支持周期和外部成本；试点数据出来前不写保证线索数量或成交的套餐。

首发跨行业验证基线为五类业务各至少两家独立企业，共至少十家，每家连续试用 14 天：制造/贸易、专业服务、软件/数字服务、本地生活、零售/品牌。实际样本还须覆盖不同客户类型与销售方式，记录具体行业、业务和来源；这是代表性抽样，不是行业允许名单，也不证明所有行业同等有效。未覆盖行业继续允许配置，明确效果未验证；不得要求穷尽全部行业才发布。

开始前冻结样本、画像版本、合格商机定义、人工基线及评测方法；收集资料、邀请客户、收费或真实外发所需授权单独取得，本次文档批准不等于已授权执行这些外部动作。至少记录：

- 此前未知、客户认可且能采取下一步行动的去重线索数；
- 人工筛选与联系准备耗时、软件辅助后的同口径耗时，以及自动运行等待时间；
- 实际联系、有效回复、下一步约谈/报价；区分技术送达与业务有效回复；
- 任务运行稳定性、干预次数、单位有效线索成本；
- 实付、实际使用和续费意向。

量化验收按以下口径执行，均为待验证目标，不是现有结果：

| 维度 | 目标与测量方法 | 未满足时的处理 |
|---|---|---|
| 首次配置 | 在资料及所需账号齐备的条件下，客户独立从空空间确认业务画像并完成首个任务配置，单次用时目标 ≤10 分钟；记录全部试用企业的用时、完成/失败及人工帮助，不把平台采集耗时混入配置时间 | 报告原始分布及未通过样本；缺条件另列，不剔除后冒称全部通过；不承诺十分钟内必有商机 |

对外定位：“意客AI｜面向各行业企业的 AI 商机工作台”。核心表达：“懂你的业务，发现有据可查的需求，让每一次跟进更有方向。”顶级体验是内部研发标杆，只有可复现的实测结果才能写成效果宣传；不宣称无依据的全网第一、全行业保证获客、全平台无限触达或自动成交。
