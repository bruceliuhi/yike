## 2. 第一批工作

先推进下面四条工作线，实施时再记录负责人及开始时间，不等最终页面定稿或生产服务器：

1. **V02-01：账号、设备与执行协议。** 定义客户会话、设备绑定/撤销、平台连接、任务事件及服务端身份边界；确定桌面接入方式，保留 Origin 防护。为 V02-02 安全候选上传和 V02-03 监控运行提供契约。
2. **V02-04 / MP-01：版本化研究 Skill。** 将现有研究规则沉淀为通用包及平台规则，定义输入、输出、工具能力、预算和反例；实际执行器接入随候选与连接器完善。
3. **V02-06：触达通道可行性。** 先核对首发通道的发送、回执、回复及收件人映射条件；准备真实来源可回查的验收对象。当前无可用对象/通道时继续协议设计，不执行未经确认的测试消息。
4. **V02-09：Windows 执行可行性。** 提前验证进程生命周期、浏览器依赖、隔离目录与凭据保护、安装与更新方案；不能到最后只套一个安装外壳。

V02-05 的[全页面设计 R3](../design/v02-suite-r3/README.md)已于 2026-09-09 获用户明确实现授权，状态为 `APPROVED_FOR_IMPLEMENTATION`，正在分支 `codex/ui-r3-desktop` 开发前端、交互、适配及客户端；基准与原话见[授权记录](../design/v02-suite-r3/APPROVAL.md)。这次整套授权与此前只选第一张 P06 方向分开记录，不追溯改写历史。V02-01 的最小身份/事件契约确定后，V02-02 与 V02-03 即可分别开始，不等其他首发平台全部完成。

## 5. 桌面、服务端与 Skill 边界

默认拓扑：**Windows 客户端＋本机平台执行器 → HTTPS 客户服务 → 私网 PostgreSQL**。这不是完整离线版，也不默认带云端浏览器。

- 桌面负责用户操作、平台登录及受控工具执行。服务器维护客户身份、任务权威状态、画像、候选/商机、发送确认与审计；租户由服务端身份解析，不相信桌面上传的 tenant_id。
- Windows 包中禁止包含 `YIKE_PILOT_DATABASE_URL`、`YIKE_PILOT_ADMIN_DATABASE_URL`、`YIKE_PILOT_AUTH_SECRET`；不得直接连接数据库或运行管理员导入 CLI。
- V02-02 必须新增受认证候选上传 API。V02-04 新增独立复核接口，由服务端确认复核人、时间、画像及证据；设备输出不能直接自报 APPROVED 成为客户商机。
- 服务端默认承担研究 Skill 编排、意向处理与证据校验，本机执行平台工具；任务记录 Skill、连接器、模型及画像版本。V02-01/04 定义工具调用与恢复协议，不能依赖一个持续打开的 Codex 对话充当生产 worker。
- 服务端 Web 进程继续仅用应用数据库连接；管理员迁移/provision/当前导包环境独立。未来原始候选和用户复核路径按最小权限设计，不把 Web 服务提升为数据库 owner。
- 浏览器会话使用每客户/设备/平台/账号专用存储。旧采集器的 Unix 进程、权限和 Python 路径检查须在 V02-09 做 Windows 对应实现；现有只读 Linux Web 容器不直接塞入浏览器会话目录。
- 桌面 WebView/IPC/认证接入不能通过关闭 Origin 检查、接受任意 null 来源或使用生产开发登录桥接解决。V02-01 明确真实来源与认证边界并测试。
- 本机离线只记“未执行/离线”，不能记“无新增”。要提供关机后仍运行的云端执行，必须另外接入有实际平台能力与独立会话的节点并验收，调度器存在本身不证明能采集。
- 浏览器/模型/发送等外部调用不占用长数据库事务；短事务提交结果时检查 owner、执行代次和当前授权。收件人、内容版本、渠道或连接身份变化都使原发送确认失效。

## 6. 里程碑与发布判定

| 阶段 | 必须证明 | 可以如何表述 |
|---|---|---|
| M1 | 多平台登录连接、逐平台真实首次采集、原始候选可核验 | 可展示已验收的采集能力；单平台贯通只是子任务 |
| M2 | 多轮增量、无新增与失效恢复、真实 Skill 意向筛选、用户复核、统一商机工作台 | 可让客户验证线索价值，仍不是完整付费版 |
| M3 | 确认后真实触达、回复回流、跟进、Windows 交付、独立审核；服务端实际部署通过 CP-06 | 满足完整付费版技术交付条件；商业效果仍需实际付费与使用验证 |

CP-06 保留私网 PostgreSQL/非超级用户 RLS/ACL、并发确认、管理员连接隔离、HTTPS、日志、备份恢复、回滚、真实手机及部署 SHA 证据。它不能替代多平台或收发验收，V0.2 功能完成也不能替代 CP-06。私有客户环境交付同样验收实际服务端环境，不能以没有公开域名为由省略隔离和恢复检查。

报价与试用范围以已经验证的能力为准；不承诺未测平台、自动成交、固定线索量或无限触达。文档审核通过只证明本文件可用，不能记为上表任一实现完成。

## 7. 进度更新与证据格式

每次实际推进只更新相应主任务，附：`任务/子项、负责人、状态、实现 SHA、验证日期与环境、执行结果、原始证据路径、已知限制、下一动作`。遇到外部输入缺失，注明阻塞的具体子步骤、所需输入和仍能继续的工作。

代码候选通过定向检查后进入独立架构、代码和质量复核，按问题修复并复审；真实验收后才标 DONE。不要复制旧测试数、把计划视为上线证据，或为了结束任务删掉尚未满足的完成标准。
