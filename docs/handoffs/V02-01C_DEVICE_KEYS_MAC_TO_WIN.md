1. 锁定包含本候选的已审核提交，记录自己的精确SHA；现有01A/B ACK不沿用为本卡ACK。
2. 通过已有有效产品会话登记新device，由服务端设置owner。历史owner=NULL记录不可直接认领。正常短信登录属于01D，不能宣传客户已能自主注册。
3. 在客户端主进程/受控本机执行器的私有存储生成设备Ed25519密钥。私钥不得进入renderer、普通IPC、日志、业务API或Git；本机私钥存储由09D另行验收。
4. 以新UUID request_id提交BIND挑战，expected_credential_version=0及规范公钥。对服务器返回的signing_payload按UTF-8原样签名，不能解析后重新序列化或改字段。只提交签名，不提交私钥或自造payload。
5. 换钥必须同时持有原私钥和新私钥，二者签同一服务器payload。响应超时先用原request_id查历史；查不到不直接判失败，更不能盲目换新requestId重复操作。
