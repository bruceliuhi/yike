# 01D：已开通客户手机号登录切片交接

2026-09-09，CodexiMac主实现。范围依据[计划](../superpowers/plans/2026-09-09-phone-login-slice.md)和已批准P01；本切片不是整个账号/激活任务完成。

## 已实现的连接

- 认证核心 `9556fab`：既有用户的不可变手机号指纹绑定、持久验证码挑战、冷却/配额、发送状态和一次性消费；独立phone_auth_task_review规格/质量通过。使用新迁移109，不改101–107，108仍留Win。
- HTTP及客户端 `f36ec97`：P01既有按钮→固定桌面请求→服务端手机号认证→HttpOnly会话→已有会话读取/撤销；不返回手动粘贴token，不改页面布局。
- 数据库只存独立认证密钥计算的HMAC；手机号/验证码仅存在处理请求及供应商发送的内存中。PhoneAuthStore.bind_user仅受信管理员使用，HTTP与普通应用角色不能绑定或创建客户。

| 固定客户端操作 | HTTP | 请求 / 响应 |
|---|---|---|
| session.requestCode | POST /api/ui/auth/sms-code | `{phone}` → `{retry_after:60}` |
| session.loginPhone | POST /api/ui/auth/sms-session | `{phone,code,trial_code?}` → `{authenticated:true,user_id}`＋安全Cookie |
| session.get / session.logout | 既有GET/DELETE /api/ui/session | 复用服务端身份和撤销，不靠客户端布尔值登录 |

phone为11位ASCII国内号码，code为6位ASCII数字；首次试用激活时 `trial_code` 为运营发放的 8 位大写字母数字码，客户端不能提交user_id/tenant_id/URL/任意请求头。已激活客户后续登录不带 trial_code；旧长码仅用于过渡兼容，运营重发统一生成 8 位码。

验证码请求响应仅说明受理，不证明号码已开通或短信送达；未知号码相同响应但不外发。发送为短事务预留→事务外单次供应商调用→短事务确认。明确接收、拒绝、未知分开；异常不重试，冷却不返还。仅当前ACCEPTED且未过期/未消费的码可登录。

## 生产入口仍关闭

正式CLI未注入phone_auth/sms_sender，`sms_login=false`，两个新路由返回501。内部集成可给build_app显式注入认证store与SmsSender；测试替身使内部能力可调用，不构成供应商已验收证明。不得给CLI随意增加开关就称真实登录已支持。

后续接入必须提供：已批准短信供应商、签名/模板、独立认证密钥和供应商凭据的安全注入、已开通手机号绑定、真实收码、HTTPS/可信代理及Windows P01退出/恢复实测。不要把密钥、完整手机号、验证码贴进本文件或Git。供应商adapter必须有有界网络超时、不重试未知发送、不保存/输出敏感异常。

迁移仍由受信管理员执行；109后执行`deploy/grant_phone_login.sql`，目标受限应用角色通过既有`yike.app_role`机制指定。该脚本不授予pilot_users目录权限，也不给普通应用绑定表写权限。不要将admin DSN放入Web环境。认证密钥必须独立、至少32字节；更换会影响既有指纹，不能静默更换后假称账号可恢复。

工程硬上限：60秒冷却、300秒有效、每挑战5次错误、号码3次/小时、来源peer10次/小时、全服务100次/小时。均由数据库持久化且重启不清零，使用滑动一小时窗口；这不是套餐或服务量承诺。可信代理未配置时同一代理可能共用peer额度，真实接入前需联验。
