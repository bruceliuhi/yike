## 对产品下一步的具体影响

基线 `desktop/src/main/publicCommunityDriver.ts` 的 `recordsFrom` 只映射 `topic.content`；`pilot/research_public_reader.py` 的 `_public_topics` 同样只保留主帖。当前代码没有取作者评论或附言。这个证据不足以判断每条需求仍开放；现有人工复核不能被采集/模型成功替代。

下一片优先验证**固定项目源的主帖→本人附言/回复→完整度→联系判断**，而非只把 `outsourcing` 加入枚举。实现前先核公开接口/正常浏览页面的数据合同和访问条件；不得假设 v1 节点 API 含作者后续更新或历史分页。本轮没有新增该连接器。

最低验收场景：

1. 类似1232232：主帖寻源仍在，但作者后续关闭，必须保留关闭证据而不是推荐联系。
2. 类似1240655：作者补充作品要求，判断及草稿能看见该条件；不能自动生成不存在的作品。
3. 只有回复头/未加载正文时，记录未读范围，不当“没有反证”；待核与明确关闭分开。
4. 同作者相关两帖和历史永久排除复用原去重/反馈机制，不因新来源、新任务或关键词重复计数。

以上是下一实现的证据要求，不是已开发能力。冻结邀请候选 `fbf9f94`、Windows阻塞和完整V0.2目标不变；本批不重跑旧模型样本或构包。
