### 1. P06 初始依赖读取没有有界等待，挂起后缺少可恢复入口 — P2 代码缺陷

- **依据与位置：** [TaskWizard.tsx:71](../../../desktop/src/renderer/pages/TaskWizard.tsx#L71) 直接读取画像、平台连接和设备信息；[hooks.ts:25](../../../desktop/src/renderer/app/hooks.ts#L25) 的 `useResource` 直接等待 loader，不设置超时；[client.ts:73](../../../desktop/src/renderer/services/client.ts#L73) 的浏览器 fetch 也没有默认超时。画像读取一直 pending 时，画像选择一直禁用，错误/重试分支无法出现。P02 的初始依赖读取有同类风险；不能把已有 AI 建议和任务启动的超时保护当成这些读取也已受保护。
- **已有测试实际覆盖：** [task-wizard.test.tsx:193](../../../desktop/tests/ui/task-wizard.test.tsx#L193) 覆盖建议等待时保存与迟到保护；第 222、253 行覆盖建议取消和 45 秒超时。这些用例未覆盖 `profiles/connections/info` 初始读取挂起。
- **下一步浏览器路径：** 启动隔离 TEST harness，进入 `http://127.0.0.1:18794/?scenario=P06&state=loading`，等待超过约定读取上限，核验画像选择是否一直禁用且无超时重试。当前 harness 的 loading 状态有意返回 pending，适合验证这个生命周期，不能当作真实后台失败证据。
- **最小修复与证据：** 复用现有有界读取封装；超时保留草稿、显示对应依赖的错误与重试；重试成功恢复选择，离页或身份改变后的旧结果不得覆盖。补初始读取挂起/重试/迟到回归和一次可见操作。

### 2. P05 → P06 从空条件模板新建会再次自动请求建议 — P2 代码缺陷

- **依据与位置：** AI 搜索条件规则第 14 行要求已保存草稿或模板优先加载已有配置、不反复自动生成。[localTemplates.ts:11](../../../desktop/src/renderer/pages/tasks/localTemplates.ts#L11) 模板保存条件时不保留 `savedAt`；第 55 行从模板新建会生成 `savedAt=null` 的草稿，仅以 `templateSourceDraftIds` 标识来源。[TaskWizard.tsx:286](../../../desktop/src/renderer/pages/TaskWizard.tsx#L286) 自动建议条件未排除模板来源。当模板有已确认画像、关键词/排除词/已删除词均为空且无建议来源时，会被当作首次空白任务。
- **已有测试实际覆盖：** [task-wizard.test.tsx:158](../../../desktop/tests/ui/task-wizard.test.tsx#L158) 证明带 `savedAt` 的空草稿不会重复生成；[task-templates.test.tsx:79](../../../desktop/tests/ui/task-templates.test.tsx#L79) 证明模板派生配置并生成新草稿，第 88 行明确断言 `savedAt=null`。尚无“空模板派生后实际进入 TaskWizard”的组合回归。
- **下一步浏览器路径：** 进入 `http://127.0.0.1:18794/?scenario=P06&recovery=ai-late`，在初次建议返回前取消生成，保存空词草稿；保持同一 TEST 会话，通过线索采集页把该草稿保存为模板，再从模板新建。核验是否无用户请求即再次进入建议生成中。不要刷新或切换 TEST 场景，否则内存服务重置。
- **最小修复与证据：** 模板派生草稿加载原配置，自动建议须区分真正首次空白任务；保留显式“生成建议”入口。补上述真实父子页面组合测试，不改变模板的祖先未知启动锁或任务请求身份。

- **最小修复与证据：** 利用已有任务/平台状态显示可追溯的提示及任务入口，真实待办优先；初次引导按实际完成度收起。保持“未知/未读取”与权威零新增区分，不增加推测业绩。
