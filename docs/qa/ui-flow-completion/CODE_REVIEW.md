## 结论依据

工作台服务为显式可选能力。四个队列分别定位候选、联系准备、回复和到期跟进，目标 ID 经过 URL 编码并在目标页按原 ID 读取。队列校验匹配类型、完整快照总数、唯一记录以及样例标记/保留 ID；错误与读取中不显示“没有待办”。请求最多等待 30 秒，资源依赖覆盖服务、身份和队列，旧请求不能填入新队列。未接工作台服务时，原有客户商机 fallback 保持“队列未接通”的说明并排除样例，不伪装成真实待联系队列。

候选精确定位使用 `ids:[requestedId]` 且固定第一页，不把当前通用筛选或列表首条误当目标。返回不同 ID 或多条记录会拒绝显示。目标切换清理勾选、当前选中、入库确认和替换判断弹窗，同时保留各候选 draft 中的未知复核记录。目标不存在单独提示已移除/无权查看的可能性；挂起请求按 30 秒超时处理，旧结果受资源代次限制。候选写入逻辑仍使用既有证据、画像和人工确认边界。

联系准备排序复制数组后按真实 updatedAt 排序，未知日期置后，不生成虚构更新时间。文字查询和排序只保存在用户隔离的本机会话。备注另存于 user/商机/画像版本限定键，最多 500 个 Unicode 字符；公开样例只读，备注不属于 ContactDraft，也不进入保存消息或发送 payload。提示明确是本机会话备注，未宣称后台客户资料已更新。

共享 ledger 新增跟进六元键和任务四元键及新启动四元值，同时保留旧启动字符串。类型、长度、动作、摘要及版本约束均在写入前校验；原有发送与管理操作约束没有被放宽。持久写失败仍抛错，清空普通草稿不移除未核对操作。Confirm 新参数默认 false，并接入真实 Button.disabled。服务契约只增加独立可选组，没有新增任意 URL/请求头/管理员凭据/文件路径通道。
