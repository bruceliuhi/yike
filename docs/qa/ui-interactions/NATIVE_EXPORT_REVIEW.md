## 结论与依据

未发现新增 P0/P1 阻断，可进入本轮候选构建和验收。

1. **输入和调用方边界明确。** 渲染进程只能提交固定的 `format/name/content`，限定 CSV 或备份 JSON、UTF-8 内容不超过 2 MiB；不能提交绝对路径、任意字段或可执行文件类型。主进程验证主窗口、主 frame 和可信文档 URL，并在保存窗口返回后再次验证。预加载只开放固定方法，原有全局下载拦截仍保留。
2. **“已保存”对应真实写入完成。** 原生窗口取消返回 `cancelled`；文件扩展名与绝对路径检查通过后，先以 `wx` 和 `0600` 创建同目录临时文件，写入、同步、关闭，再替换目的文件，之后才返回 `saved`。写入或替换失败返回固定错误，并清理本次临时文件。渲染进程拿不到所选绝对路径或异常中的路径详情。源码中的 `0600` 是 POSIX 创建权限参数，不能据此宣称已经验证 Windows ACL。
3. **取消、重复与迟到结果不制造成功。** 主进程只允许一个保存窗口，重复请求不排队。P10 在等待回执时禁止重复提交；取消和失败保留选择，离页或身份切换后忽略旧成功提示。保存窗口本身由用户决定何时结束，没有把等待超时错误描述成文件写入已经撤销。
4. **导出业务范围准确。** CSV 仅取勾选的客户记录，排除公开研究样例；所有字段引号转义，并对可能被表格程序执行的公式前缀添加文本前缀。浏览器下载只返回 `initiated` 并提示用户确认，缺少原生保存接口的旧客户端返回能力不可用，不回退到被拦截的下载路径。
5. **测试与包证据边界准确。** 测试覆盖原生实际临时文件写入、替换失败清理、取消、繁忙、frame 失信、错误后缀、晚到回执、浏览器发起与旧桥缺失。打包冒烟脚本在隔离 Electron 进程替换保存对话框，但执行实际包内 IPC、校验和磁盘写入并读回字节；这只能证明该被测包的保存链路，不能证明真实用户对话框体验、Windows 安装或生产备份恢复。文档已明确新能力必须对新 ASAR 重新运行，不能沿用历史包结果。
