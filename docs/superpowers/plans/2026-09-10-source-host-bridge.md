# Fixed source host bridge

**Goal:** Connect the existing main-only CollectionDriver interface to the governed Windows Python driver and existing formal mapper, without generic subprocess IPC or backend credentials in source processes.

**Architecture:** Main-owned fixed Python/project/runtime/profile/output-root options; spawn only `python -X utf8 -m app.windows_collection_host`. One bounded JSON line carries a confirmed search snapshot-derived query, cap/time and formal mapping context. Keep stdin open during work; EOF or any subsequent input cancels. Python owns Windows Job cleanup via existing driver, maps raw records through `build_comment_batch`, then emits exactly one bounded JSON result line. Node synchronous start returns a stop handle, uses signal to close stdin and waits for actual host completion; forced host termination is a stop failure, not confirmed cleanup. No renderer process paths or arbitrary commands.

For the first bridge, execute one driver invocation per confirmed query sequentially, under one total record/time cap. Preserve raw directories per invocation, select unique identities without silently replacing conflicting content, and retain per-record query. Unsupported links/research/exclusions cannot be silently ignored; reject until represented in the source bridge. Do not enable normal UI capabilities merely because this internal bridge compiles. Profile binding to authenticated connection and the actual main worker factory remain required next.
