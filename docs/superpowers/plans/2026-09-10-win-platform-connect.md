# Windows platform connection implementation plan

> Agentic workers: use subagent-driven-development, TDD and one final independent SPEC then code/quality review. User authorized autonomous implementation and compressed checks; no repeated design approvals or whole-suite/build cycles.

**Goal:** Make the existing account page actually open an isolated XHS login browser, identify the logged-in account, and register/verify its versioned connection without exposing cookies or granting collection/sending capability.

**Architecture:** Reuse governed runtime, Windows private directory/Job cleanup, existing account page and owner-scoped connection operations. A main-only controller owns service/user/device/platform profile references and pending registration/verification UUIDs. Fixed Python login host launches the installed runtime interpreter and a fixed browser worker; no generic shell/renderer paths. Browser performs only normal home/self-account read and user login, no search/send. Server VERIFY is an authenticated owner-device declaration of a fresh local check, not independent platform attestation or execution authority; existing fresh lease/device signature/capability fences remain unchanged.

**Alternatives:** An Electron-only second cookie store would duplicate the collector profile; copying cookies into requests would expose secrets and sever account binding. Use the same private Playwright profile instead. A new cryptographic attestation protocol cannot prove browser truth and is unnecessary for this owner-scoped status declaration; retain existing device proof for actual execution.

## Runtime login (helper, independent files)

- [ ] Create `app/windows_platform_login.py`, `app/platform_login_worker.py`, and focused tests. Fixed request `schema_version=windows-platform-login-v1`, `runtime_path`, `profile_path` (new or verified private), `output_path` (new), `platform=XIAOHONGSHU`, `timeout_seconds` integer1..180. No service/DB secrets. Main trusted paths only.
- [ ] Windows host stdin one bounded strict JSON line; EOF/any additional byte requests cancellation. Existing runtime/profile mutex + runtime hash/private ACL checks, create private profile only if absent, Windows Job supervisor, minimal env and installed Playwright Node/browser paths. Worker stdout sanitized single JSON (max16KiB), decoded only after whole process tree stops; host reports `AUTHENTICATED` with `account_public_id` and UTC `checked_at` or explicit WAIT/FAILED/CANCELLED/TIMED_OUT. Any unknown cleanup -> `SOURCE_HOST_FAILED`. Host never maps failure to no data.
- [ ] Worker imports pinned XHS crawler/client/login under installed runtime cwd. Launch same persistent Chromium/default UA, go to official home, initial pong; if unauthenticated wait for user via governed login then refresh cookies and recheck pong. Extract unique canonical official `/user/profile/<id>` from the existing self-navigation (label 我), never arbitrary profile links/nickname/cookie ID. No QR export, SMS click, secret entry or captcha bypass. Close context before return. Emit an `OPENED` marker in private output directory only after actual visible browser launch; main polls fixed host STATUS read to avoid claiming a mere spawn opened a window (implementation may use fixed stdout progress if simpler, freeze with root).
- [ ] Tests execute real worker logic under controlled browser/HTTP boundaries, Windows host argument/env/privacy, actual EOF/cleanup. No real account/login without user action. Root provides installed runtime `.runtime/windows-installed-xhs-20260910-02` unchanged.

## Connection VERIFY (helper, backend only)

- [ ] Extend existing `ConnectionOperation` with action `VERIFY`: canonical connection_id, positive expected version, and exact platform/account_public_id/session_ref (same validation as REGISTER). Read current owner ACTIVE device + exact connection under existing lock order; compare platform/account/session_ref and version, reject DISCONNECTED and mismatches as connection_unavailable/conflict. Only update status CONNECTED; existing107 trigger increments on actual state change, repeated fresh verification of alreadyCONNECTED leaves version unchanged. Max-version state transition returns existing exhausted code. Historical original UUID remains immutable and does not prove current status.
- [ ] Add `migrations/119_v02_connection_verification.sql` replacing only action CHECK to include VERIFY, idempotent; register in `pilot/db.py`. Do not modify historical migrations or RLS/grants. Existing POST/GET connection-operations routes retain strict fields, HTTPS/Origin/session, owner scope, bounded fixed errors. Registration remains UNVERIFIED. No capability enable, browser/network or new generic authorization framework.
- [ ] Tests RED/GREEN strict model + actual restricted PostgreSQL HTTP for register→verify→current fence, duplicate UUID, stale version, wrong owner/session/profile/account, disconnect race, atomic receipt rollback. Existing registration/disconnect regressions only; independent reviewer checks authorization and version semantics.

## Desktop composition (root)

- [ ] Main-only connection service policy uses the existing private request queue/epoch scope, fixed REGISTER/VERIFY/GET original request routes. Renderer command accepts only OPEN/CHECK/CANCEL with platform XIAOHONGSHU; cannot provide account/profile/status/session_ref/device claims.
- [ ] Persist main-owned profile/reference and original operation UUIDs before sending, OS-protected and service/user/device scoped, recover original receipt before retry (no automatic new UUID on timeout). Local login result is scoped to original authenticated epoch, has <=120s check freshness, never reused across login/logout/device changes; exit/cancel waits physical cleanup. REGISTER from fresh actual account then VERIFY exact returned version; unknown outcomes stay explicitly recoverable, not CONNECTED. Reject account mismatch/reuse from another device. Preserve profiles; never delete cookies as an unrequested cleanup action.
- [ ] Wire existing main/preload/service `connect` and `checkConnection` plus CANCEL on modal close, without layout redesign. Return CONNECTED only after exact successful VERIFY receipt and current scope check; capabilities stay empty. Main-owned runtime configuration from developer-only absolute paths until customer bootstrap bundle is packaged; missing/unsupported runtime reports actionable unavailable, not READY. Do not expose developer paths in UI.
- [ ] Targeted Node/controller/renderer tests and actual fixed Node→Python protocol, Python tests/PG, typecheck; one independent batch review, fix only deltas, integrate main. Visible real login/action requires user and will be checked in the final acceptance candidate, no new package while worker/task integration is incomplete. Remaining next: collection account-recheck, main worker/journals and backend finish/capability, actual three-channel intake and contact loop.

Base `366559d`. Prior XHS patch/source/bridge evidence reused. Legacy collector28 Windows/POSIX failures remain documented, not hidden; do not re-run that unrelated suite. This connection slice does not complete the product Goal or redefine live acceptance.

**Final interface decisions after SPEC review:** The host response is at most one `OPENED` frame after the real browser launches, followed by exactly one terminal frame after Job tree cleanup (not the earlier single-frame/STATUS alternatives above). OPENED is emitted by supervisor poll_callback observing a bounded private worker marker. Before renderer CONNECTED, GET current connections and require exact original device/platform/account/id/version/status; a session_ref mutation necessarily increments107 version, so equal version also fences that reference. An old VERIFY receipt alone never upgrades the UI. If no current tuple match, require a new user-initiated login/check rather than resurrecting a historical result.
