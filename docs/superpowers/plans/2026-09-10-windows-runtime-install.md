# Windows governed runtime installation

> Execution: subagent-driven-development for the independent native directory task; root owns installer composition. One combined spec/code/quality review for this batch, then delta review only. User's compressed-verification and autonomous implementation instructions override repeated approval/full-suite gates.

**Goal:** Turn the successful manual Windows dependency/CLI/Chromium probe into an executable, fail-closed installation command. This is an engineering installation entry, not a claim that the desktop worker, XHS adapter, installed customer app or account connection is complete.

**Design:** Reuse the current governed upstream commit, patches and dependency digests without altering the POSIX lock contract. A separate Windows provisioner resolves `.venv/Scripts/python.exe`, the bundled Playwright Node and browser cache. Create only a new explicit absolute destination, with current-user/SYSTEM/Administrators ACL from creation; do not overwrite/adopt an existing directory. Every subprocess uses the existing Windows Job supervisor and a restricted environment. Install pinned uv dependencies with `--link-mode copy`, then run CLI and local-only Chromium probes. Write a Windows installation receipt last; no old `.yike-runtime.json` or platform capability flag. Any failure leaves the private partial installation for diagnosis and no success receipt. No credentials, login or external contacts.

Alternatives: a PowerShell copy of the full installer would duplicate validation and error handling; changing the existing POSIX collector would couple this step to legacy SQLite execution. Use a Python Windows provisioner plus native ACL helper, both callable by the later worker/bootstrap. Supplied Git/uv executables are trusted operator/bootstrap inputs, never renderer paths. Customer bundled bootstrap remains a later wiring step.

## Chunk 1: Native private installation directory

- [ ] Create `app/windows_private_directory.py` and `tests/test_windows_private_directory.py` with TDD. API `create_private_directory(path: Path) -> Path` creates only the leaf atomically with protected inheritable ACL; parent must already exist. Reject existing leaf, nonabsolute/local drive paths and reparse ancestors. `verify_private_tree(root: Path) -> None` reads the full tree, rejects reparse points and multiply linked files, unexpected grants, null DACL and wrong owner. It never repairs existing permissions or shared caches. Import-safe on POSIX with explicit unavailable error.
- [ ] Test native inherited directories/files, refusal without changing existing data, hardlink and widened ACL rejection, and path guards. Run only this Windows test module.
