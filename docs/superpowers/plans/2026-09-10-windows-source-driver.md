# Windows source driver implementation plan

> Agentic workers: use subagent-driven-development and TDD. User-approved autonomous lean scope and one batch review supersede repeated approval/review ceremonies.

**Goal:** Execute the installed governed source through Windows Job lifecycle and retain bounded original output ready for the existing candidate mapper. This is actual driver infrastructure, not platform readiness or customer acceptance.

**Architecture:** A main-only Python driver accepts trusted runtime/profile/new-output paths and one confirmed keyword, bounds time/records, validates the local installation receipt/governed bytes/private directories, and launches only the fixed upstream main command with isolated environment and profile. Existing supervisor waits for process-tree cleanup before output consumption. A separate reader pairs raw comments with their actual source using exact IDs and converts only the governed millisecond observation field; no trim, invented author, nickname linkage or duplicate truncation. No legacy SQLite Collector, alternative crawler, backend/mapping edits or readiness bypass.

**Scope:** Governed patch currently supports bili/dy; reject XHS until Mac-controlled profile/terminal and mapping prerequisites arrive. Single-keyword driver is composed per confirmed query by the later client bridge; never silently drop extra configured keywords. Auth/challenges are user actions. No actual platform requests during this implementation batch. Runtime Python and data directories are operator/main-owned inputs, not renderer-supplied executable paths. Caller must serialize all use of a runtime/profile and invoke only for a live authorized execution; this library does not grant execution authority.
