# 单次多平台采集与原任务续接

基线 `09ad94bb7bd5c29f03bede29e207874109c63a4a`。落实 AUTHORITY 已批准的多平台任务主链，不新增平台、后台权限或外部发送。

## 约束

- 复用既有三平台监控串行执行机制，单次任务允许三平台模式下小红书/抖音/B站的有序子集；旧 xhs-only 模式仍仅一个小红书。确认策略平台顺序、全部账号/设备/版本及快照摘要必须吻合，启动前全部检查。
- 单次/监控共用一个执行槽；各平台一个原 platform_run，一个原 CLAIM，不并行开浏览器。后一个平台开始前重新核对原用户/会话/设备/账号；取消、身份变化、未知结果、物理停止未确认均停止后续执行。
- 一个任务的 max_records 为所有平台共享上限。按确认顺序固定均分（余数给前面的平台），不返还过滤/重复/未使用额度；最小上限不得小于平台数。每个平台 worker 使用自己的分配上限，但原确认快照不改。单平台旧行为不变，监控使用相同分配规则。
- 多个原上传批次可以依次恢复回执/FINISH；只恢复当前任务、原平台run、原设备/凭据版本的不可变批次，拒绝重复/陌生/冲突映射；RECOVER 不打开浏览器，不生成新采集请求。原 UNKNOWN/404 不证明未执行。
- 原 START 显式重试可继续安全未执行的后缀：已完成前缀必须有当前服务端 SUCCEEDED、对应本机原 CLAIM/上传/FINISH，并核对真实原回执；未执行后缀必须当前 generation=0/PENDING 且无任一非START原操作或批次。任何缺失/未知/不一致不开始新来源。不能重新执行已 CLAIM 平台；原任务到期/撤销/取消/账户变化仍由当前核验拒绝。监控轮次不提供手工来源续接。
- 客户详情页仅提供主动确认后的“核对原上传”和“继续未执行平台”，使用现有固定IPC，不新造后端协议。先同设备核对/原请求读取，再使用原START的requestId重试；页面状态切换/退出后不得继续。恢复成功不能夸大整任务完成。
- 不做全量回归或重复构包；新增行为的最小失败→通过、一次独立全批审核、一次renderer build。无真实平台/模型/消息/生产调用。
