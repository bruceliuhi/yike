# Native stop receipt — design and implementation plan

Goal: close a canceled native collection only after its bound device confirms physical source termination. This batch repairs the observed permanently CANCELLING native task path; it does not claim recovery of old processes without evidence or completion of the customer trial.

Authority: user approved autonomous technical refinement and asks for one focused verification/review/build batch. This single document combines design, plan and evidence; do not generate duplicate reports. Work on main is explicitly authorized, preserving unrelated changes.

## Design

Use a new internal signed execution operation `STOP` with task_id, platform_run_id, lease_id and execution_generation, plus the existing device, credential and request identity. No renderer command can fabricate it. Existing operation serialization remains byte-identical. STOP receipt binds those fields and reports aggregate CANCELLING/CANCELED plus stop_confirmed.

STOP only accepts native tasks already CANCELLING/CANCELED; current authenticated owner/device credential and exact stored platform lease/generation must match. Deadline or lease expiry does not invalidate a stopping acknowledgement, but it never grants execution. Profile/connection revocation must not prevent stopping; revoked device/session still fail closed. Research tasks reject STOP. SUCCEEDED tasks/platforms are never downgraded. A platform CANCELED status represents generation-zero never-started or acknowledged stopped; CANCEL preserves already terminal platforms and marks pending generation-zero CANCELED, other unfinished platforms CANCELLING. Only when every platform is SUCCEEDED/CANCELED does aggregate status become CANCELED. No timeout-only confirmation, no mutation of historical receipts, no record deletion. All updates are under the existing task locks and tenant RLS.

The worker returns an internal stop proof only after driver.stop resolves, bound to its original validated claim; failed physical stop yields no proof. Controller first persists STOP into the existing private execution journal after this proof, then uses a fresh scope matching the original user/session/device/credential to reconcile cancellation and submit the exact stop request. Only canceled work is acknowledged; a successful finish or unknown upload/finish must not be converted to canceled. Existing durable execution recovery handles a recorded STOP; it must not launch the source. If session changes or proof is absent, retain the uncertainty. Old interrupted tasks without this durable proof stay unresolved and must not be auto-acknowledged.

Rejected alternatives: treating expired leases as physical stop invents evidence; a new general supervisor/management subsystem is unnecessary for this bounded cancellation repair.

Review corrections: a persisted STOP must be sent using `execution.recover(session, requestId, true, originalDevice)` after confirming server cancellation, not submit (which would only query an existing record). The receipt-not-found fence permits only that saved request to be sent. Update both get_task and _feed_item stop_confirmed predicates and ensure repeated CANCEL preserves terminal platform states. Exclude STOP from _mutate execution-version/cancellation gates and _apply post-write execution-liveness checks, while preserving signature/active owner/session/device/exact lease and generation checks. A worker stop proof is eligible only before candidate upload dispatch; once upload or FINISH was dispatched, preserve/reconcile its original unknown outcome instead of manufacturing a canceled outcome. Upload/finish cancellation races receive explicit regression tests. This batch does not auto-acknowledge those unresolved outcome paths.

Session clarification: immediate completion callbacks require the original user/sessionId/device/credential scalars. On restart, recovery of an already durable STOP uses the existing journal's same owner/service origin and exact original device/credential under a freshly authenticated session, guarded throughout each request; it need not retain an in-memory sessionId from before restart. This re-signs only a saved physical-stop statement, never launches source work. Historical immutable receipt reads retain existing semantics; new STOP effects require current signed authority.
