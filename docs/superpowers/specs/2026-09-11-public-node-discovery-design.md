## 设计基线时已核查的限制和来源

- 设计基线的普通公开采集 `publicSource`、服务能力和 driver 仅允许 `v2ex-latest-v1`；研究编排同样固定最新帖子，但属于另一条有资源许可的执行链。本片后普通采集扩为两个固定来源，研究不变。
- [V2EX 官方维护者说明](https://www.v2ex.com/t/1187622)确认 v1 `topics/show.json?node_name=...` 可读节点最新主题；分页需要带 token 的 v2。不能将 v1 节点抽样宣传为历史搜索。
- 2026-09-11 本机只读一次 `https://www.v2ex.com/api/topics/show.json?node_name=qna`：HTTP 200、JSON 数组10条，全部节点名为 qna，均含正文、发布时间、URL。只输出结构计数，未保存作者、正文或联系信息；这不是10条商机，也不是产品已读取。
- 多业务画像实体及具名版本选择已实现；本轮不因字段仍为自由文本就重建该功能。

## 选择

1. 继续扩大首页关键词：实现最少，但无法增加实际检查范围。
2. **采用固定来源目录，先接 V2EX 问与答板块**：已有原文格式可复用，能先验证“选来源→确认→读取→入候选→监控”的完整流程。
3. 任意URL、任意RSS或直接加入多站点：需要各站点内容、错误和权限合同，不能只开放输入框后宣称支持。

选2作为下一片，随后逐个具名站点评估；不声称单一技术社区足以满足各行业，不默认加入招聘或供应商广告。

## 确定合同

- 来源ID仍是版本化固定枚举：原 `v2ex-latest-v1` 保持原字节；新增 `v2ex-qna-v1` 只映射上述固定HTTPS节点接口。用户/模型不能传入URL、host、node_name或重定向目标。
- 只扩展普通采集/周期抽样；`research != null` 的搜贝研究仍只允许原最新索引，不能因枚举增加将新来源交给旧固定研究reader。
- 新部署模式 `four-platform-public-node-monitor-v1` 保留四平台能力，显式允许两种公开来源单次/定时抽样。旧模式保持原允许集合，绝不默默扩大旧任务。
- foreground/monitor capability在旧 `public_source` 之外提供可选 `public_sources`，内容为固定ID非空、无重复数组，包含旧默认ID；只有新模式返回该字段。新客户端缺字段时仍只知道旧默认来源。
- 本机公共绑定携带同一设备下的可选来源目录。每次准备/开始/恢复/监控执行，都按当前能力核对所选来源；旧服务不能接受新来源。返回不认识的ID或不一致目录拒绝，不转成默认来源。
- 任务草稿新增可选 `publicSource`。旧草稿仅在选web时默认原最新索引；新选择进入配置快照/摘要、模板、恢复及最终确认，修改后原确认失效。一次普通任务只选一个公开来源，不偷偷多请求或补扫历史。
- 复用原V2EX字段映射、正文不改写、同平台+外部ID去重、候选上传与观察。collector_version记录所选固定来源ID；QNA响应每条须核对 node.name=qna，不能把其它板块回执标成QNA。
- 复用1MiB/20秒/任务记录上限；最多一次GET，不自动重试、分页或跳转。两个板块共用同一driver冷却，不通过换来源逃避60秒间隔。身份、取消、过期和设备围栏保持。
- 普通原任务/监控界面按快照标出具体板块、抽样和过滤范围；不覆盖历史/全站/评论，不把采集空结果写成该行业无商机。历史确认不是当前执行许可。
- 不新增账号凭据、价格、扣费或自动发送；无数据库迁移需求。新服务与客户端需配套验证，不能将旧严格解析客户端兼容视为当然成立。

## 纵向实施顺序与定向验收

1. 后端：`pilot/research_strategy_contract.py`、`foreground_collection.py`、`monitor_runtime.py` 接固定枚举及新模式。专项测试证明旧模式拒绝QNA、新模式允许单次/版本1日程、research路径拒绝QNA，以及配置摘要/原请求恢复保留来源；旧配置序列化不变。
2. 客户端：shared合同、`foregroundCollectionController.ts`、`publicCommunityDriver.ts`、草稿/模板/确认页和监控绑定一并接入。专项测试证明固定URL、节点不匹配拒绝、两源共享冷却、预算/取消保持、旧能力不显示新选择、改源重新确认、重开不回退首页。
3. 使用隔离身份与受限PostgreSQL验证普通确认→来源读取→现有候选上传→同ID复跑只加观察；一次显式真实QNA读取保留统计与可重开来源证据，不将其计作合格机会。真实测试不调用发送或激活客户试用。
4. 整批非作者审核、差量修正后合main；不自动部署、不重构冻结邀请候选。Windows实机和客户效果仍分别待验。源码变化前按本合同形成具体实施计划，不只增加菜单。
