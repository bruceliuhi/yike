# 研究资源收口状态（非财务结算）

范围：完整 V0.2 的研究用量接续，按 AUTHORITY 的既定技术授权实施；独立于冻结 b40cc3b 邀请候选，不部署、不重新构包。

现状：资源事件在 PostgreSQL 持久化，但页面只展示“请求数”和“待结算”。ISSUED 仅是执行许可，不证明网络调用发生；进程中断后可能一直没有回执。现有计量规则仅定义上限估算，失败、缓存、等待时间的实际折算及价格未经批准。

方案比较：直接按许可折算会编造实际消耗；现在新增金融账本会提前锁定未批准语义。因此先复用持久事件，提供只读资源收口状态，金融结算保持未完成。不是用这一子项替换完整结算要求。

## 合同

既有状态 DTO 的 usage 增加可选 `resourceCloseout`：`{state, overduePermits, asOf}`，asOf 为本次数据库一致性快照的 UTC 时间。旧服务缺字段时客户端显示尚未提供，不猜测已收齐；旧客户端严格 DTO 不兼容新字段，未来发布必须绑定同版服务与客户端，当前不部署。客户端比较是否取得新进度时忽略仅 asOf 的变化，不因此重复推进。

- `OPEN`：仍可继续的任务，暂无未决异常。
- `DRAINING`：有未过期的 ISSUED 或执行租约，尚在等待回执/执行者退出。
- `UNCERTAIN`：有 UNKNOWN、过期仍 ISSUED 或待确认分析结果；超时不推断外部执行结束，不重试、不扣减、不释放。
- `RECORDED`：task 和 run 均为真正终态，且无未决事件、分析结果或执行者租约。仅 coordinator.STOPPED 或 CANCELLING 不能证明终态。仅表示当前资源记录已收齐，不表示研究成功、商机有效、搜贝结算或余额释放。

`overduePermits` 是数据库时刻下已到 deadline 的 ISSUED 数量，不另加进 unknown，原五项计数恒等式不变。不会修改原事件，迟到 finish 仍按原许可幂等落库。

状态和计数来自同一次只读一致性快照（任务、协调器、资源事件）；分析结果独立读取只能保守阻止 RECORDED。优先级为 UNCERTAIN > DRAINING > 终态 RECORDED > OPEN。`actualSoubei=null` / `settlementState=PENDING` 保持；不新增金融表、默认规则、收费、释放余额或新的外部动作。

页面改称“来源许可/模型许可”，分别展示成功/失败/待回执/未知，另显示超期未核实数和资源状态。只改变现有进度文本，不改 R3/R4 布局或操作权限。

## 验证与未完成项

定向真实受限 PostgreSQL 验证完成、取消前后在途/迟到回执、过期许可、UNKNOWN、租约、跨身份读取；确认 status 不更新事件、不发请求。TS 严格验证数量与状态矛盾，UI 验证旧服务与新状态文案。隔离合成 I/O 只证明协议，不证明真实平台或收费。仍需计量规则确认、最终结算账本、更多来源、Windows 与真实客户验收。
