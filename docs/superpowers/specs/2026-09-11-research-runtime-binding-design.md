# R4研究启动：来源、估算和执行绑定

状态：V0.2内自主细化；2026-09-11用户授权允许实施。相似来源进入确认策略已实现于18c37b7，限定证据及审核见[来源记录](../plans/2026-09-11-similar-research-provenance.md)。确认版本只读估算组件与客户端接线已实现于8626329/81d06bc，2386ccc复核GO，见[估算记录](../plans/2026-09-11-confirmed-research-quote.md)。原子START/资源预留及客户端私有传输已实现，a18aa9a差量复审GO，见[启动记录](../plans/2026-09-11-atomic-research-start.md#实施证据)。运行时仍未装配研究worker及规则，页面未启用；预算许可、实际资源事件和结算尚未实现。本文不是搜贝比例、价格或生产启用批准。

## 当前证据与决定

- 普通`services/client.ts`已装配确认版本的researchUsage估算请求；研究启动尚未装配，TaskWizard继续拒绝research启动。保护不能先删除。
- 原诊断中`strategyPrepareRequest`与Python/共享TS合同均拒绝来源；18c37b7已接相似研究provenance及服务端当前资格核验，coverageProvenance仍拒绝。服务端升级前仍不能使用新来源合同；不将本批当成研究启动完成。
- 本机`configurationHash(taskFingerprint)`没有executionLimits，不能成为搜贝估算/预留唯一依据。已有服务端`configuration_sha256`覆盖完整确认策略和执行上限；必须复用它，并继续核对本机草稿版本、账号选择与可信账户空间。
- 采用“完善原策略合同→确认策略后估算→同事务预留和START→真实资源事件→结算/恢复”的路线。拒绝两种捷径：把research去掉当普通once跑，或只让估算按钮返回数字。二者都无法兑现用户确认的研究范围与上限。

## 1. 先锁定完整研究意图

沿`research_strategy_contract.py`、`shared/researchStrategies.ts`及`strategyPrepareRequest`扩展可选来源字段；缺字段时不增加null键，不改变旧快照摘要。保留demandTypes、limits、stopAtAnyLimit、evidenceOrder和来源身份，任一改变必须新策略版本。

相似研究来源绑定当前用户、账户空间id/version、原机会、画像版本、原文URL和证据版本。服务端复用既有`OpportunityResearchService._recognized`及当前认可校验，不能信任客户端自报“有效”。需要新增同事务来源校验入口，避免另开连接在检查与确认间留下窗口。准备、确认、执行解析都校验适用来源；历史回执只作历史读取。

现有requestId/suggestionId、originalScope/additionalScope属于建议溯源，不自动成为采购事实或执行授权。必须明确哪些能由服务端原建议重算/回执核验；不能把未经核验的客户端说明标成系统已证实。覆盖补查来源另沿`SearchCoverageService`保留原task/run/window及预算修订，不能把它当原任务重启。未接通的来源类型继续拒绝，不能静默丢弃。

## 2. 估算绑定已确认服务端快照

普通客户先准备并确认策略，再估算该版本；估算请求携带策略id与服务端configuration_sha256，同时回显现有草稿id/revision与可信账户空间。客户端本机hash只用于编辑失效检测，不替代服务端hash。

版本化计量规则只能显式配置，没有生产默认换算；缺规则或执行能力时显示尚未接通，不返回虚构0。测试使用明确命名的合成规则，不成为部署配置。保留“上限估算”的依据，不将最坏上限称作预测实际消耗。

quote是无副作用计算：不建任务、不预留、不扣减。可使用服务端签名的短期凭证绑定完整输入、规则摘要、有效期与quoteId；确认令牌只在页面内存，日志和恢复账本不保存令牌。START阶段才持久保存非秘密quote摘要及消费唯一性；不得一面称只读一面写用量或扣减记录。

## 3. 同事务预留和任务创建

研究启动使用专用认证入口和已签名设备START，不修改旧操作的签名/摘要字节。研究报价凭证置于外层信封，服务端验证当前身份、设备、平台、确认策略、来源、规则和上限后，在原请求锁及同一PG事务内写预留、任务/运行/平台行、START回执。失败全回滚；同quote不能另建任务；同请求内容冲突拒绝。

旧执行入口不得接受research后忽略用量。返回UNKNOWN时仅核对原请求，确认“未受理”必须有服务器证据；凭证过期与请求未知不能合并为可安全重发。旧UUID/任务历史仍按原协议恢复，不因引入新hash改写已有回执。

## 4. 真实资源与用户可见结果

读取尝试、已接收候选、独立来源、模型调用与商机数量分开；不得把入库条数直接宣称成实际读取数。固定源和模型worker在执行动作前取得预算许可，动作后提交带task/run/代次/事件幂等键的实际记录；前端不能自报计量。失败和未知是否计量由显式规则说明，未知不能猜成0。

同一预留在并发、取消、超时、FINISH和回执恢复间使用事务锁核对；消费不超过预留，扩大上限必须新估算和明确确认。释放仅发生于确认停止且资源事实已结算之后；保留停止请求、实际停止、结算中和已释放的差异。仍执行SOURCE_MATCH_CONTEXT固定补证顺序和任一资源上限停止，不以普通搜索替代完整研究。

## 实施顺序及验收

1. 完整来源进入策略准备/确认/解析与客户端回读：真实原文绑定、跨租户/画像/版本反例、旧快照字节兼容。
2. 可信估算及普通页面接线：配置变更失效、过期、规则缺失、空间变化、无副作用；不开放启动。
3. 原子研究START、预算许可和实际worker：受限PG并发/回滚、真实controller-worker链、保留补证顺序/意向类型、错误与取消。
4. 结算与恢复、普通结果页面：丢回执不重复动作，不以模拟数据证明真实消耗或商机质量。

按上述依赖实施完整功能，不把第一片当R4完成。每个可验收批次只跑受影响定向检查并做一次非作者审核，稳定后统一构包；真实模型/平台、Windows与生产/跨行业验收继续单独执行。
