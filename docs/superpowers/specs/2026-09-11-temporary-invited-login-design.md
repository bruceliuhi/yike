# 短信未接通期间的受邀体验登录

用户于 2026-09-11 要求线上暂用“手机号＋手机后四位”，避免短信申请阻塞主流程。后四位可从手机号直接推导，不是身份认证秘密。本实现保留其输入体验，但不能把后四位当作任意既有账号的登录凭证，也不把它记为手机号已验证。

## 最小用户路径

运营后台预开通独立体验空间 → 通过已建立的联系渠道交付专属体验登录凭证 → 客户输入手机号、后四位和专属凭证 → 服务端建立正常受限会话 → 原画像/任务/商机/跟进主流程。

第一版复用登录页现有试用码输入位置，明确标记“体验访问码”。凭证必须每次新建登录会话验证，不能激活一次后退化成仅后四位登录。已有有效会话继续复用，不增加主流程页面。邀请链接自动填充作为后续体验优化，本批不承诺已实现深链；不将凭证置于会进入代理日志的 URL query。

## 边界

- 默认关闭，部署方显式启用且配置截止时间，过期停止新体验登录。短信能力故障不触发自动降级；正式 SMS 路径和验证语义保持独立。
- 仅运营新建的 trial 账号可获邀请；禁止给正式客户、管理员或其他既有空间签发。号码绑定与新租户创建复用运营模块，不能按提交的号码/tenant_id 直接选择用户。
- 邀请凭证至少 192 bit 随机，独立用途摘要、仅展示一次、可撤销和过期，绑定服务端解析的特定账号与号码。现有“一次性试用权益码”不能不改语义直接用作长期登录密码。
- 四位 ASCII 数字必须等于提交号码后四位，只是输入校对；真正授权由专属凭证完成。未持有凭证时，即使知道完整手机号和后四位也必须失败。
- 邀请登录激活体验权益可与身份来源分别记录；不使用 OTP challenge 的 ACCEPTED/consumed 状态伪造短信成功，不标记 phone_verified。默认体验期限沿用运营已批准的 72 小时，不另改价格或权益。
- 复用受限数据库连接、租户隔离、HTTPS/Origin、HttpOnly 会话、停用/到期失效规则。认证尝试受有界持久限速保护；未知号码、凭证错配、撤销或过期统一失败，不输出号码是否已注册。
- 新建会话寿命不超过邀请/体验/入口截止剩余期限；停用邀请后的已有会话处理必须在实现时明确并验证，不能只关闭登录按钮却声称撤销生效。
- 不记录原始手机号、后四位、邀请凭证到 Git/日志/导出。后台全手机号仍只走已授权的加密运营展示。

定向验收必须覆盖：开关关闭/截止拒绝；后四位单独无权登录；错号码、错凭证、错后四位拒绝；正式客户/管理员拒绝；仅已邀请新 trial 成功；到期/撤销旧会话失效；失败限速不回滚；短信路径不降级；登录页面不请求短信、不显示已发送/已验证，真实会话确认后才进入工作台。
