# AI 项目商机研究

版本：`1.0.0`。本包是 V0.2 的研究 Skill 规则层，不是平台连接器、调度器或发送器。

输入：卖方画像、历史去重台账、平台/时间范围、研究预算和用户排除项。
输出：带原文证据的 S/A/B+ 候选卡、`SEND_READY / REVIEW / OBSERVE / EXCLUDE` 操作状态、独立的公开评论和私信草稿。
允许的动作：读取授权公开来源、打开可重现原文、提取证据、分级、写草稿和记录覆盖。
禁止的动作：自动评论/私信/加好友/发送、绕过 Cookie、验证码、限流或风控；外部发送必须由用户人工批准。
运行预算：单批次 30–60 分钟；默认主队列最多 10 条，其余合格项目进入去重总池。

目标是找到有原始证据、值得销售联系的独立需求，不是填满名单。行业和技术词是搜索种子，不是允许名单；买方不必知道 AI 术语。只有明确改变服务边界时才重新问用户。

## 开始与延续

- 先读任务的当前队列，再读卖方画像、历史线索和用户反馈；注明画像版本及本轮时间。历史报告是当时的证据快照，不是今天的推荐名单。没有历史台账就说明历史去重未完成，不宣称净新增或可立即触达。
- 首次使用可先交付价值排序；用户确认无历史触达，或完成其提供的已知/已触达名单核对后，建立带覆盖范围的去重基线。不要要求不存在的全历史数据让任务永久停在 REVIEW；也不要把已有大量触达但记录不全当作首次使用。
- 区分用户确认能力、公开服务宣称、已核实案例和待确认能力。不要把店铺宣传、低价起步套餐或“理论上能接”转成已交付案例、固定报价、全行业资质。
- 当前任务授权优先；本 Skill 只研究、分级、写草稿。发信、加好友、改自动任务、部署不在其中。只操作授权公开来源；遇登录失效、验证码、风控即停止受阻路径并报告，不换账号或通道绕过。

## 研究

首次采样、扩大搜索或线索不足时，完整读取 [搜索与覆盖](references/search-and-coverage.md)。按“买方业务问题 → 可交付物 → 寻源/付费动作”扩词，结合站内搜索、近期版块、主帖及独立作者的评论；不要困在单一 KOL 或搜索引擎摘要。

每个候选判断前，完整读取 [资格与证据](references/qualification-and-evidence.md)。取需求作者自己的原文、时间、联系路径与反证。预算未知、匿名或只有评论路径可保留；订阅询价、硬件支出和技术讨论不能冒充开发采购。

## 交付

按研究价值输出优先机会、适配待确认、观察和排除；每条另列操作准备。S/A/B+ 是研究优先级，SEND_READY / REVIEW / OBSERVE / EXCLUDE 是操作状态，不是发送授权。S/A 与操作 REVIEW 可以并存：历史去重或入口权限未完成，不应单独抹掉研究价值。每批默认最多 10 条主队列；其余有效项目保留在去重总池，不让展示上限限制采样或每天只研究一次。

卡片写：项目与需求作者、需求时间、原文/定位方法、业务问题、购买对象、动作/预算证据、价值判断、关键反证、联系路径状态、历史去重状态、下一步。事实与推断分开。缺失写未知。

推荐交接前填完[当前核验行](references/qualification-and-evidence.md#当前核验行与队列)：作者更新读到哪里、最强反证、入口与历史核对。发现作者楼层缺正文等明确缺口，保留研究等级，但进入待补证，不混入“今天值得联系”。过期或关闭项目进入历史排除，不用观察池继续养着。

在任务已有台账维护唯一当前队列；没有则建立 `current-queue.md`。按“可交接、待补证、观察、排除变更”分栏并带证据链接。闭环纠错先更新它，再在旧报告加撤回提示；不覆写历史事实。

每条公开评论与私信分别写：一处原帖细节 + 一个易回答的问题，通常 25–60 字，最多一个信息请求。别把接口、规模、预算、验收四项藏进同一句；不在首次开场索取样本、推付费 PoC 或堆产品介绍。不虚构案例。长诊断清单留给对方回应后。

## 复盘与继续

报告实际覆盖、独立项目数、合格/待核验数及主要损耗原因，而非“全网搜完”。完整验证或修订本 Skill 时读 [验证与反馈](references/evaluation.md)。无合格项先查覆盖/访问/误筛；有合格项无回复则分别查可达性、账号可信度、文案和观察期。不能仅凭文件测试通过或冷信无回复判断商业成立/失败。

画像、查询台账、真实证据与反馈存任务输出目录，不写进个人 Skill。不要持久化 Cookie、口令、验证码、登录令牌、完整私信历史；来源 URL 清除会话凭据并保留可复现定位步骤。
